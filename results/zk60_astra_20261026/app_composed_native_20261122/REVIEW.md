## Five-switch classifier release, November 24

The W16R2 runtime now selects the prover built from merged commit `da8546e7a`, SHA-256 `3a540c08b3cc00d559e3cd44ed38c6ab45cdc4007087e03b3503bb08f068da8f`. The service gives the prover the fused RS, sparse fold, sumcheck chain, host-fast and classifier host-fast settings. Both verifier launch paths remove all five variables, including ambient values. The installed app can still recheck its two earlier signed W16R2 publication formats. The service retires a native process that exceeds its request deadline so a later job can start a fresh process. All 307 Python tests and four frontend suites passed with the new pin. [Build](classify-host/BUILD.json) · [Regression results](classify-host/TESTS.json)

Three archived benchmark sets contained 864 native prover completions. All 648 separately checked requests matched their native checker IDs. The eight-thread host-only comparison gained 1.55% and 0.55%. Adding the classifier switch on the same candidate gained 6.09% and 2.62% at eight threads, and 10.07% and 6.51% in the five-thread confirmation. These are public-stream benchmarks. The earlier app's 28.61-second post used another binary. [Per-leg logs and rates](classify-host/BENCHMARK.json) · [Reader](review_host_fast.py)

The five-switch release passed a fresh installed-app run in an isolated local store. The resident prover produced 28 segments for each of the three categories. The independent verifier accepted all 84 and reported a 97-bit floor in every category. The post took 33.17 seconds. This is one end-to-end qualification observation. The evidence includes the separately run public-store checks and clean guard exits.
