## Findings

### High

**H1. The corrected wire runner's agreement theorems still hold by mutual refusal; no Lean
statement shows an accepting run.** (READ)
- D26WireOpen681.lean:375 `wire_frame_agrees`: `advance ... false raw s = advance ... true raw s`
  (an `Except`); 401 `wire_run_agrees`: equality of two `Option`s; 423 `wire_candidate_agrees`:
  `wireCandidate ... false ... = wireCandidate ... true ...`. The proofs close the `.error` and
  `none` branches by `rfl` (lines 381, 386, 411, 431).
- So each theorem is true when both sides return `.error` / `none`. Nothing in 681 (and no
  `example` in 681 or 689-703) exhibits inputs on which `advance` or `wireCandidate` returns
  `.ok` / `some`. This is the pattern Sol's correction describes for 677/679 (agreement by mutual
  refusal); the correction itself proves the old schedule refuses
  (`row_count_check_refuses_canonical_columns`, 681:25) but does not prove the new one accepts.
- Document D26_WIRE_OPEN_681_682.md:28-30 says "both runs return the same whole-run candidate
  and ordered opening tape". The Lean statement only says the two `Option` values are equal.
  Acceptance of the new schedule rests on the Python replay 682 only
  (doc lines 31-33, "matched all 37,400 selected occurrences"), which I did not run.
- Same pattern, eight newest files (READ):
  - D26ModelFold689.lean:276 `folded_family_slot_agrees`: `step ... true ... = step ... false ...`;
    no accepting case.
  - D26PairedWire697.lean:137 `emitted_record_replays`: `runPlan ... left ... true = runPlan ... right ... false`
    under `same : left = right`; docstring (134-136) and document (697 doc:11-13) say "including
    refusal"; no accepting case.
  - D26PairedMask699.lean:226 `reached_mask_reader`: conclusion `matchedRead ...`, and
    `matchedRead` is `True` on `.error _, .error _` (D26AdaptiveBody621.lean:91). No accepting case.
  - Not this pattern: 691, 693 and 703 (implications from an `.ok` hypothesis, or pure algebra);
    695 `distinct_compiled_candidates_observe_same` (695:394) requires both candidates to return
    `some` (`leftOK`, `rightOK`), so refusal cannot satisfy it, but no instance shows the
    hypotheses are jointly satisfiable. 695:343 and 701:264 take `some (out,left)` directly.
- Why it matters: an "agreement" theorem of this shape cannot distinguish a correct runner from
  one that refuses every canonical receipt, which is exactly how 677/679 went wrong.
- Possible remedy (for Sol): one lemma per runner that some concrete input is accepted, or a
  statement of the form `left = .ok x -> right = .ok x`, or a replay-in-Lean on a small
  retained frame.
