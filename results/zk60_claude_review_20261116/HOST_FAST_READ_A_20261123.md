## Findings

**M1. Whole-proof on/off identity is tested only on Metal, and only when a test is run by name.** `w16r2_tests.rs:4710-4713, 4838-4841, 5219-5222, 5577-5580` [code]. All four whole-proof tests are gated on `feature = "gpu-metal"` and are `#[ignore]`. H1 to H3 are plain CPU/rayon code with no `cfg`, so they turn on in any build, including the planned RTX 5090 (CUDA) box. In that build, and in the default `cargo test`, only the unit tests (`zk.rs:2266`, `range16.rs:352`, `protocol.rs:3340`, `accuracy_act.rs` h1 test) check them. **Fix:** add one test with no `#[ignore]` and no feature gate: the CPU `seeded_digest` of `W16R2_RUNG_H24` with the switch off and on, plus the toy legacy shape, asserting equal digests and nonzero H1, H2 and H3 hit deltas.

**L1. The per-block log line also counts other lanes' hits.** `protocol.rs:2512-2514, 2770-2771, 3105-3116`; `zk.rs:127-149` [code]. The counters are process-wide atomics, and the line prints end-minus-start deltas. The a22 harness runs its lanes in one process (`run_fork_tests.rs:7092-7103`, `set_a22_lanes_for_test`) [code]. So a block whose own H1 fell back could still show `h1>0` because another lane hit in the same window. "No fallback across the run" still holds overall, because any fallback increments a global counter [inf]. The claim "every component active in all 312 blocks" is not established per block [inf]. **Fix:** count hits per block through a thread-local or a counter passed in by the block; or reword the smoke claim to process-wide totals.

**L2. The test override exists in release builds and races with tests that skip the lock.** `zk.rs:177-188` [code]. `set_host_fast_for_test` is `pub` and not `cfg(test)`. Today it is called only from `cfg(test)` modules (`private_block.rs:70-75`, `run_fork.rs:3268-3270`) [code]. Only the unit tests take `host_fast_test_lock`. Ordinary proof tests running at the same time silently use the fast path while a locked test holds `Some(true)`. Those concurrent hits can also satisfy the `ha > hb` non-vacuity asserts (`zk.rs:2301`, `range16.rs:372, 391`) [inf]. **Fix:** mark the override `#[cfg(test)]`; make the non-vacuity asserts read per-thread counts, or count hits inside the call under test.

**L3. H3 puts 80 KiB on the stack in every rayon task.** `range16.rs:257-259` [code]. That is `[usize; 2048]` plus two `[Fp2; 2048]`. Rayon's default 2 MiB worker stack holds it. A pool built with a small `stack_size`, or deep nesting caused by work stealing, could overflow. That is a crash, never a wrong value [inf]. **Fix:** use per-chunk `Vec`s, or `for_each_init` with reused buffers.

**L4. The first fallback of each kind is printed even when HL_METAL_TIMING is unset.** `zk.rs:205-210` [code]. The text is a fixed string, so nothing about the witness is printed. Every H1/H3 reason depends only on alpha, beta, gamma, the public tables or the shape, because a lookup miss has already been refused at `protocol.rs:2433` before `CoreAhead` exists [code]. The per-block counts line is gated on both variables (`protocol.rs:3105`) [code]. **Fix (optional):** gate the fallback lines on `host_fast_timing_on()` as well, or document them.

## Checked and found sound

- **H2 draws (zero knowledge).** `zk.rs:623-660` [code]. Every draw runs on the calling thread before any parallel work, in the order masks, then the pads of each row (re, then im), then `b_re`, `b_im`, `u_re`, `u_im`, then the salts (`:634, 640-645`). The old code (`:668, 674-685`) draws in the same order. The only move is that the salts are drawn before encoding, and encoding draws nothing (`encode_coeffs_coset` at `:558` and `ntt.inverse` take no generator). The parallel closures cannot reach `rng` (it is `&mut`, and the closures run under `Fn + Sync`). Rows are paired with output chunks by indexed `zip`, so the result does not depend on scheduling. Pads are written to `msg[len..len+MASK_Q]` exactly as before. Production uses `ZkRng::from_os` (`zkp-core/src/rng.rs:289-301`): an OS-random key feeding the same deterministic stream. The seeded tests therefore exercise the same draw code, with only the key source different [code]. The `assert!` fires at the same point relative to the draws (`:633`).
- **Verifier independence for H1 to H3.** `mask_commit_tagged` is called only by provers (`protocol.rs:2513`, and the `token_io/stage_*.rs` calls). `denominator_inverses` is called only from `prove_core_after_with` (`protocol.rs:2804`). `fill_exp_helpers` and `fill_act_helpers` are private and called only at `:2867` and the line after it. `verify_inner_at` is unchanged [code]. No verifier code reads the switch in this scope.
- **H1 exactness.** The cached path requires `exp_missed == 0` (or `act_missed == 0`). These counts come from `exp_histogram`, `act_histogram` and `accuracy_act::histogram` (`protocol.rs:484-535`, `accuracy_act.rs:59-75`) on the same witness and block. The `CoreAhead` shape check and block-pointer check are at `:2764-2769` and `:2338`. A hit means the index is in range and the looked value equals the table's value. The field is canonical (`zkp-core/src/field.rs:20-28`), so the table inverse and the per-row inverse are the same word. ACT3 groups and padding match `query_group` and `denominators` (`accuracy_act.rs:52-54, 102-116` against `write_helpers_from_inv`). Tables are rebuilt in every call from this call's alpha, beta and g, so nothing is cached across blocks or lanes. A zero in a table falls back to the old code, unchanged, at the same point, and the old code gives the same refusal string, including the chunked `inverses` variant (`:1010-1022`). Skipping `table_helper` when the A18 switch (`tab_on`) is set is safe: the cached path is used only when no table entry is zero, and `table_helper` (`:2044-2049`) then gives the same words [code].
- **H3.** `range16.rs:246-282` [code]. A zero denominator gives `None` at the same index; there is no panic on either path. Chunks are always full (n is a power of two of at least 2048, and CH = 2048). `(alpha - g) - v` equals `alpha - (v + g)` exactly, in canonical form. The result does not depend on the thread count.
- **Switch off.** With the switch off, the code that runs is the old code. Added on every run: three new `CoreAhead` fields, about 20 relaxed atomic loads, and `table_values_exp` built inside the loop instead of before it (it cannot fail). `act_table` and the refusal order are unchanged (`protocol.rs:2961-2994`) [code].
