# HOST_FAST read B (H4, H5, H6): review of a7faf0ddb..6b68cb931

**Verdict: merge with named changes.** One change: M1, a CPU proof-parity test that runs by default. L1 is cheap and is advised. I found no fault that gives a wrong proof, an accepted bad proof or a privacy loss. Tags: [code] = read in the code; [inf] = inferred. Line numbers are at 6b68cb931.

## Findings

**M1. No proof-level parity test runs by default, and no test covers the build without `gpu-metal`.** [code] The four proof-level host-fast tests are all `#[ignore]` and need `gpu-metal` (w16r2_tests.rs:4712, 4840, 5221, 5579). The tests that run by default are unit tests of H4 (accuracy_fold.rs:626-781) and H5 (argument.rs:3696). So the CPU-materialised `PubGen` path, the fold cache across slots and the scalar H4 path have no proof-level check in the normal suite. A build without `gpu-metal` never compiles any of these proof tests. **Fix:** add a test that is not ignored and needs no GPU: `seeded_digest` on the W16R2 rung with `set_host_fast_for_test(Some(true))`, asserted equal to `W16R2_RUNG_GOLDEN`, holding `host_fast_test_lock`.

**L1. The `direct_total` guards check domain sizes but not the table layout.** [code] argument.rs:2563, 2596, 2733 enable `direct_total` when `size(D) == t_pad*d_pad` (and the S/Ht equivalents). They do not check that the plane's log (`b.a_log(plane)`) equals the slot's main cube `n`. They also do not check that `r_t`/`p_ht` has length `log t_pad` / `log Ht`. [inf] Today A_X, A_X1, A_E and A_ZSEL are on the slot's own domain, so the closure equals `total(&tables, poly)`; test Part 2 (w16r2_tests.rs:5398-5449) checks this on two shapes. A later profile with a broadcast plane would give a wrong claimed sum. Because the round polynomial is recovered from that claim (`recover_one`, argument.rs:~1756), the verifier would reject the proof: a liveness fault, not a soundness one. **Fix:** add `b.a_log(plane) == sh.slots()[slot].0 && point.len() == lg(..)` to each guard.

**L2. The new kernel is compiled even with the switch off.** [code] metal.rs:3872 adds `mk("k_tab_pub_gen")?` to the one `TAB_PIPES` build. If that kernel fails to compile on some driver, every A12 device table build is declined, even with HL_HOST_FAST unset. The bytes stay the same (the host builds the tables), but proving is slower. Start-up cost is otherwise one pipeline, built lazily. **Fix:** make `pub_gen` an `Option` pipeline and decline only PubGen jobs when it is missing.

**L3. The verifier arm has dead prover-side code.** [code] The `Side::Verify` arm now branches on `def.pub_gen(i)` (argument.rs:1896-1903). The shared length check consults `pub_gen` too (1576-1584). Neither runs in production, because `pub_gen_prove` is set only for `Side::Prove` (3601). **Fix:** refuse, or `debug_assert!`, when `!def.pub_gens.is_empty()` on Verify. Then a future caller cannot make the verifier depend on `PubGen`.

**L4. Test overrides are process-wide.** [code] The H5 unit test sets host-fast and `set_lazy_for_test` for the whole process (argument.rs:3705-3706, 3762). Its `Drop` resets lazy to `None`, which can overwrite the setting of a concurrent A14 test. Other tests running in parallel may take the fast paths during that window. **Fix:** take one shared test lock for every lazy/host-fast toggle.

## Checked and found sound

- **H4 exactness [code].** `split_signed_fp` (accuracy_fold.rs:63) gives limbs `lo, hi ∈ [-2^31, 2^31-1]`. The extreme `s = -(2^63-2^31+1)` gives `s-lo = -2^63` exactly, with no i64 overflow. Each product is at most 127·2^31 < 2^38 in magnitude (128 only for refused input). Each i64 lane takes at most `rows` products (row axis) or `cols` products in total after the horizontal add (column axis). At `HOST_FAST_MAX_DIM = 2^20` (line 40, checked at 503) the sum stays below 2^58. Overflow would need 2^25 terms, so the margin is 32 times. Recombination happens in i128 (below 2^91), followed by an exact `reduce128`. Each `v·a_i` in Fp2 is computed componentwise, as `fold_rows_i8`/`fold_cols_i8` do (zkp-core mle.rs:157-198). Inputs are canonical, so `P-u` cannot underflow [inf: `mul_base` output].
- **i8::MIN refusal [code].** The same shape checks run first, then the same `FOLD_ERR` string. Every row or column is either scanned inside the accumulation by vector min (start value 0, so the min is -128 exactly when -128 is present) or by `slice_has_i8_min` (zero rows, column prefix and suffix, lines 455-457, 287-294). The early exit only skips chunks once an error is certain. `fold` is pure, so the refusal comes at the same call and before any transcript write. Above 2^20 the old code runs.
- **Tails and unsafe code [code].** Chunk lengths are 256 or `cols` (a power of two). Under 16 the scalar loop runs. Load and store offsets stay at or below `k+15 < len`, with `assert!`s on the lengths (152, 330). The NEON loads need no alignment, and the four accumulators are distinct arrays. A build without NEON compiles to plain i64 loops and `contains`.
- **H5 [code].** The cache key (cm, slice offset, fixed point, n_vars) plus the eligibility rules (one slice with coefficient ONE, identity `Rho` tail, `coords.len()==log`) fixes every input `priv_table_fill` reads; `ext_round` and `mask_row` are not read (547-790). The cache is a local in `argument_with` (3604), so it lives for one block and one side and is never shared between lanes. Entries are inserted only on the host path, only for SC_QMM/SC_GMM, and only with the switch on (1012, 1093). The tiled fill uses the index layout `idx=(z<<n_vars)|x` of the M9 form, with `eqf` in MSB order, and the exact `LazyDot` sum. With `HL_ARG_LAZY=0` it falls back (567).
- **H6 tables [code].** The BoxSupp/HeadSupp descriptors (2157-2180) match `Geom::support` (witness.rs:539-610) and `head_slot` (shape.rs:2322) for D, T, F, Kv, L, Tab, Dd, Q, Ht and S, including lifted cubes. `tile_rep` refuses as before. GroupCol, CausalMask and the repeat descriptors equal `group_column`, `causal_mask_at` and the old maps; `dd_e_column` length is `cap`. The device kernel (metal.rs:3738) has the same integer expressions as `materialize_into`, with matching argument order and a 56-byte struct. Validation is at 4242. A declined plan, `DT_HOST`, sync or `BATCH=0` all reach host materialisation.
- **Verifier independence [code].** On `Side::Verify` the builders run with `pub_gen_on=false` and produce the old vectors. `direct_total` is never built there.
- **Default off [code].** Every new branch is gated by `host_fast_on()`, `pub_gen_prove`, an empty `pub_gens` or `direct_total: None`. The `direct` predicate reduces to the old one. Public wrapper signatures are unchanged.
- **Concurrency [code].** The new global state is counters, test overrides and the read-only `TAB_PIPES`.
