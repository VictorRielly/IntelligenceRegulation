## 3. 374: the "actual compact M component" (C)

What it is. CHECKED from `probe_compact_mask_rank374.py` and `d78_mask_rank324.py`: for each of the 8 stages (4 stages x 2 modes, "outer" and "scaled", of the two saved compact receipts) it takes the public mask functionals the verifier derives (each functional is a weighted sum of per-slot mask-polynomial coefficients in Fp2), builds the coefficient matrix (one column per slot coefficient, slots assumed to have independent mask variables), and eliminates it. "Rank == number of functionals" means the functionals are linearly independent, which is a necessary condition for the masked values not to leak a linear relation. It also checks an exact "constructive minor" (a nonzero square sub-determinant) and that the source functional weights and order match the descriptors.

The numbers. Ranks 8/28/28/20 per mode, 84 per mode, **168 rows** in total. Recomputed from the saved `stage-0N.json` files: all eight ranks reproduce (`m_rank_probe.py`, using Sol's elimination module). The 374 report recount gives 168 rows and 32 controls. CHECKED (`m374_report.py`, `m_rank_probe.py`).

The 32 controls are 4 per stage: (a) duplicate the last functional, expect rank loss and the exact refusal "CFS mask functional rank loss"; (b) zero the first functional's weights, expect rank below the count; (c) zero the challenge, expect "M minor nonzero CFS premise"; (d) alter one weight, expect "M minor source functional weight/order correspondence". So 24 are exact-reason refusals ((a), (c), (d)), and 8 ((b)) only assert that the rank drops, without running the refusal path. All 32 mutate something and then fail or lose rank for the stated reason. CHECKED by reading the code and the retained report. My own extra control, which 374 does not have: replace the last functional by `3*row0 + 5*row1`. Rank drops by one at all eight stages (`m_rank_probe.py`), so the rank test does have teeth against a linear combination, not only a literal duplicate.

What is and is not claimed about privacy. CHECKED (report fields and scope text): `whole_view_privacy_established: false`, `formal_Lean_theorem_established: false`, `independent_slot_mask_variables_required: true`, `executed_native_mask_reuse: false`, and the scope says A/H/row-padding/boundary/joint-view/adaptive nonlinear/repeated-proof privacy and fresh independent sampling are unproved. "SS alias full rank still not privacy" means: the report identifies the two SS (norm) coefficient blocks of stages 1 and 2 algebraically (as if the same mask were reused) and full rank survives (28 of 28, four cases), so the rank test cannot detect that kind of mask reuse. I went further (my own, `m_rank_probe.py`): collapsing every group of equal-geometry slots onto one slot still leaves rank 28 at stages 1 and 2 (20 slots become 12 distinct), while stages 0 and 3 do lose rank (8 to 7, 20 to 18). So at the block stages the rank gate is blind to aliasing of equal-shaped slots; it is a necessary-condition check on the functional set, not a freshness or hiding check. Sol says this; I confirm it and that the evidence supports saying it.

NOT CHECKED: the constructive-minor determinants (I did not re-derive them), and the elimination code is Sol's, so my rank reproduction is not an independent implementation of Fp2 elimination (I read it; it is a standard sparse leftmost-pivot elimination).
