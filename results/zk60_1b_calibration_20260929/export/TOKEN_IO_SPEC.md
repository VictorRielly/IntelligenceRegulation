# Token I/O of the calibrated TinyLlama integer stack (lane B4, 2026-10-17)

How layer 0's integer input `x_in_L00` is produced from token ids, and how the
integer output of layer 21 maps back to next-token logits. The final norm and
the LM head stay OUTSIDE the proved stack (ruling D13); this spec is what the
token-generation milestone needs on both sides of the proved blocks.
Calibration/interface data, not a proof, not a privacy claim.

Reference implementation: `b4_token_io.py` (same directory as this export
tree's parent); it reproduces every exported `x_in_L00` and the logits the
fidelity numbers were computed from.

bf16 → float32 is exact: the float32 bit pattern is the bf16 bit pattern
shifted left by 16.

## Rotation (rotated exports only: `*_rot1_*`)

`R = H diag(sign) / sqrt(2048)`, H the Sylvester Hadamard matrix
(`H_1 = [1]`, `H_2n = [[H_n, H_n], [H_n, -H_n]]`), `sign` the float64 ±1 vector
in `rotation_sign.bin` (= `numpy.random.default_rng(1).integers(0, 2, 2048)`,
1 → +1, 0 → -1). R is orthogonal. Row vectors throughout:

* forward `x' = x R^T`: in float64, `y = x * sign`, then the in-place
  butterfly for `h = 1, 2, 4, …, 1024`: for every block start `i` (step `2h`)
  and `j = i … i+h-1`: `(y[j], y[j+h]) ← (y[j] + y[j+h], y[j] - y[j+h])`, then
  `y / sqrt(2048)` (float64 `math.sqrt`).
* inverse `x = x' R`: the same butterfly on `x'`, then `* sign / sqrt(2048)`.

The block weights of a rotated export were built as `W' = W diag(gamma) R^T`
for q, k, v, gate, up and `W' = R W` for o, down (all gammas folded; the
int8 gain vectors carry the rotated norms' per-channel gains), so the stack
computes the original model in the basis `x' = x R^T`.

## Layer-0 input (exact integer path)

For token ids `t_0 = 1 (BOS), t_1, …, t_{T-1}`:

1. `x_t = float32(E[t])` (exact bf16 widening).
2. rotated exports: `x'_t = float32(forward_float64(x_t))` (round to nearest even
   when casting the float64 result to float32); unrotated: `x'_t = x_t`.
3. `x_in_L00[t, i] = floor(float64(x'_t[i]) / s_in + 0.5)` (round half up),
   which must lie in [-32768, 32767] (otherwise the input refuses; no clamping).

The map is per token and position-independent, so it is a PUBLIC lookup table:
`embedding_int16.bin` (int16 little-endian, [32000, 2048], sha256 in
`token_io.json`) gives `x_in_L00[t] = table[t_t]` exactly. It was generated by
steps 1-3 and checked against every exported sequence's `x_in_L00` before
writing. Prefer the table: it removes all floating point from the input side.

## Output side (float, outside the proof)

From the int16 output of layer 21, `X = x_out_L21` [T, 2048]:

1. `x' = float64(X) * s_out`.
2. rotated: `x = float32(inverse_float64(x'))`; unrotated: `x = float32(x')`.
3. float32 RMSNorm as in HF Llama: `var = mean(x*x)` over the 2048 channels (float32),
   `h = x / sqrt(var + 1e-5) * norm_weight` (float32).
4. `logits = h @ lm_head^T` (float32); next token = argmax over the 32000 logits
   (numpy's first-maximum tie rule).

These are the exact steps behind the reported top-1 agreement, perplexity and KL.

**Equivalent form for a future proved head.** RMSNorm is rotation-invariant
(`||x'|| = ||x||`), so the head can act in the rotated basis directly:
`logits = (x' / rms(x')) @ W_head'^T` with `W_head' = lm_head diag(norm_weight) R^T`
(fold the gamma, rotate the columns). That is the same shape as a block's
norm + matmul (the integer norm relation with a uniform gain, then an int8
matmul and a requant), so a proved head would reuse the block's relations with
32000 output rows.

## Generation (what changes with the token count)

The proved block takes all T positions at once (prefill). For a generated
token the stack is re-run on T+1 tokens (no KV cache in the current relation
set): the RoPE tables are `rope_tables_generate(T, 64, 10000.0, 7)` for the
proved T, the softmax windows are shape-driven (`wrho_s = clog2(T) + f_e`),
and the calibration constants of an export are valid for the T they were
calibrated and checked at (the `*_cal128` exports share weights across
T = 32 / 64 / 128). The integer embedding of a new token is one more table
lookup.
