## 6. Pitfalls met this leg

- **Heartbeats are per declaration**: a long proof that is fine piece by piece can time out as one theorem
  ("(deterministic) timeout at `whnf`" reported at the theorem's first line). Bisect with sorry-truncated probe copies
  (`lean <probe>` steps in one plan; the probes in results/ are untracked, contain `sorry`, never commit them) and split
  the proof into lemmas.
- **A declared `have h : shdIncDataK … vH = shdIncDataK … vT := shdIncDataK_head …` with `set` variables timed out**
  (the unifier unfolds the structure). State pointwise field facts instead (`shdIncDataK_tok_head` via `simp only
  [shdIncDataK, stgPlK]` and `stgIOX_head`).
- **Concrete extractor, again**: `have htw : (EXTB …).tokW = fun t => … := epxIO_tokW ..` hits "maximum recursion depth".
  Move the rewriting into a GENERIC lemma whose conclusion is stated on the projection (`epxIO_hXI`, `epxIO_hpl`).
- **Do not apply those generic lemmas with `..` or `_` for the commitment's arguments at the concrete top**: the
  unifier then unfolds `colOf`/`epTokenCommit` and the job blew past 24 GiB (guard KILL, exit 75, twice: iter130,
  iter133/135). Give every argument explicitly, and for the hXI one use `by have h := epxIO_hXI <all args, row and col
  explicit>; exact h`. Run such probes with `L63_CAP_GIB=16` so a runaway fails fast.
- `shieldS0.Tok`'s bound is not `128` to omega: `have ht : t.val < 128 := t.isLt` (a bare `have := t.isLt` fails).
- Section variables used only in a proof are not included; to call a section theorem positionally from a later top,
  make the section variables implicit around it (`variable {tag Lq …}` / `variable (tag Lq …)` in the generator) and
  pass the remaining ones by name; a `Prop` variable such as `hR` must be passed by name (`(hR := hR)`), it cannot be
  inferred.
