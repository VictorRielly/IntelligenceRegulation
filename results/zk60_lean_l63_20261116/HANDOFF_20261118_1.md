## 4. Pitfalls met this leg

- **Elaborator blow-up on the concrete extractor**: any defeq between a readable form (`InSat Rp.inp (fun t => …)
  (bndPlanes …)`) and the projections `(EXTB …).tokW`, `.planes 0`, or a direct `rfl` for `epW = tokW`, at the concrete
  instantiation (CinB, RkDLB, …) fails with "maximum recursion depth has been reached" (maxRecDepth is banned by the
  source scan). The same `rfl` is instant in the generic lemma. Fix used: state the premises on the projections, and
  close the conjuncts with GENERIC equation lemmas applied by unification (`epxIO_epW_tokW ..`, `epxIO_xC_planes (hLb :=
  …) (hrow := rfl) ..`). Applying the generic iff lemmas with all explicit arguments also blew up.
- **Notation hygiene**: a `local notation` whose body names a section variable (`E0`) captures that variable; if the
  theorem does not mention it in its statement, the proof sees "unknown free variable". Use a notation argument
  (`local notation "EXTB" e:max => …`) or an explicit binder.
- `(classifyModelP Rp).PubOut` is not reducibly `ℕ` for instance search (`LE`, `OfNat` fail; a `: ℕ` ascription does not
  help): state the verdict as `s.verdict` (`ypub s := s.verdict`); the defeq with `ypub` is accepted where `OutOkP`
  expects it.
- `omit [Fintype K] [DecidableEq K] in` before a docstring'd theorem that does not use them (unused-variable warning).
