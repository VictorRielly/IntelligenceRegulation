## 6. Pitfalls met this leg

- **`set x := e` with a theorem binder whose TYPE mentions `e`** (`b : Fin Vi.pub.tiLog → Bool`, then `set I :=
  Vi.pub`) leaves the goal on a shadowed copy `b✝`; `linear_combination` then fails with two different atoms. `revert
  b` before the `set`s and `intro b` after.
- **A let-bound function in a goal** (`let r := …` introduced by `intro r`): `ring` sees `r 3` as an atom; `simp only
  [r]` first.
- **Two `match` expressions that print the same are different auxiliary matchers**: `rw [h]` with `h`'s side written
  out again fails to find the pattern. State the target form with `have h' : … := hev` (defeq check) instead.
- **`rw [lemma … _ … (by tac)]`**: the term is elaborated (and the `by` blocks run) before the rewrite unifies the
  holes, so a `_` that later proofs depend on (a `Priv` the hypotheses mention) is unknown. Give it explicitly, or use
  `refine (lemma … _ … (by …)).trans ?_` with every proof argument a `by` block (delayed until unification).
- `ZPart` inside `namespace ZK60.ProtocolClassify` with `open ZK60.Exec` resolves to the wrong structure; write
  `Block.ZPart`.
- `rhoC lo hi` has `hi − lo` coordinates (`ptK_rhoC`'s bound is `q < hi − lo`, not `q < lo`).
- `Fin.addCases` on `a : Fin 19`: `change Fin (7 + 12) at a` first.
- `Block.Coord.fixed.inj hw; subst` instead of `cases hw` when the constructor argument is still needed.
- The `.done` marker of `run_guarded.py` can be read directly after a foreground run of the waiter (`> /dev/null`);
  builds of one new file take 4-16 s.
