   >>> B-FINDING. The memo prices the three TABLE helpers at
   `3 x row width` (3,072 at rung-G, 49,152 at 125M).  The code
   inverts `table_values_*(...)` which is `table_values_*_at(
   Dom::Tab.len(), ...)` -- and `Dom::Tab.len()` (layout.rs:163) is
   the TOY's 256, not `sh.size(Dom::Tab)`.  So the table-helper term
   is 3 x 256 = 768 at EVERY shape.  The raw figure moves by less
   than 0.01 bit, so this is an erratum, not a finding of substance;
   but it also means the lift argument the memo gives for N-3 is not
   needed for the table families -- they never grow in the first
   place.

B. FINDING N-3 RE-DERIVED.  alpha is drawn at protocol.rs:684, AFTER
   beta (:682) and gamma (:683) and after the A and M roots, so
   conditioned on the transcript so far the whole set of denominator
   ARGUMENTS is fixed and alpha is uniform on Fp2 (the memo's own
   wording omits that beta and gamma are also conditioned on -- it
   matters, because two of the three families' arguments contain
   beta).  The bad event is exactly `alpha in S`.

   S, family by family, for any witness `Witness::new` admits:
     u8       alpha - (v + gamma*TAG_U8),   v = cst + sum c_p plane_p
              `byte(p)`   -> v = p        in [0,256) by witness.rs
              `scaled(p,k)`-> v = k*p     in [0,256) (byte(p) also present)
              `sym(p)`    -> v = p+127 and 127-p, in [0,256) for p in [-127,127]
              at a PADDED position every non-exempt plane is 0 (ruling P-1)
              so v = cst, which is 0 or 127 -- still a byte.
              => at most 256 distinct arguments
     exp      alpha - (d + beta*e + gamma*TAG_EXP), (d,e) a row of the
              256-row exponential table; witness.rs:533,639 REFUSE a
              witness with d outside 0..256  => at most 256
     act      alpha - (i + beta*a + gamma*TAG_ACT), i = g8+128  => at most 256
     u8/exp/act TABLE helpers: `table_values_*_at(256, ...)` enumerates
              exactly the 256 rows of each table, so each is a SUBSET
              of its own family above and adds nothing.

   |S| <= 3 x 256 = 768 per block, at EVERY shape.
   per block: 768/p^2 = 2^-118.42   (memo: 2^-118.42)
   12-block run, L independent alphas: 9216/p^2 = 2^-114.83   (memo: 2^-114.83)
   VERDICT on N-3: the arithmetic and the bound both reproduce.

   Two corrections to N-3's SCOPE, neither moving the number:
   (i)  the memo conditions on 'an honest witness'; the right and
        stronger conditioning is 'any witness `Witness::new` admits',
        because the byte ranges are REFUSALS in the constructor
        (witness.rs:290, 374, 386, 394, 534, 555, 600, 640, 672, 708),
        not a property of honesty.  That is exactly Lemma S's own
        hypothesis, so the term is in scope after all, and GS-12 can
        be closed for the u8 and exp families rather than carried.
   (ii) those same range refusals are R-1's INPUT-DETERMINED refusal
        sites.  Pricing the LogUp-denominator term over the admitted
        witnesses is right, but it must be said that the conditioning
        event itself (admission) is input-dependent and is governed by
        operating rule M-9, not by this term.

   BUT the backstop is never reached.  B-CHECK 2 computes the maximal
   minor's determinant EXACTLY and it equals
     prod_g Norm(lambda_{g,j(g)} * cm_{j(g)}) * wedge(rho_prox pair)
   on every seed.  A product of norm forms vanishes iff one factor
   does, and each factor vanishing is a NAMED refusal
   (protocol.rs:246 / :284-286 / :289-290).  So 'bad set subset
   refusal set' is an IDENTITY, conditional only on `audit_claims`
   giving each group a member with a pair of its own
   (protocol.rs:259-272).  Schwartz-Zippel is not the argument and
   its unusability at run scale costs nothing.
