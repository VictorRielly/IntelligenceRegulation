## Summary verdict

**SOUND WITH FINDINGS.** No soundness defect and no privacy leak was found in the production code.
- No prototype safeguard was lost on the move.
- No cheating path, test hook or test-only identity is reachable from a release build or from the CLI.
- Registration is exactly as specified. Each base has its own constructor domain, refusals hold in both
  directions, and the door checks marker + base.
- The on-disk reader is as strict as D12a's.
- The worker count changes only scheduling.

**One Medium finding (F3) must close before any receipt for real content.** It is D60's own precondition,
and it is enforced nowhere in code:
- no privacy gate, Rust or Python, has read a capture under a REGISTERED profile;
- the registered header bytes have never been independently replayed.

The Low findings are evidence and robustness gaps:
- F1: the D55 verifier's own preflight has no negative control;
- F2: no release-binary run at L ≥ 2 or N ≥ 2;
- F4: the reader's no-follow / no-block open does nothing on macOS, now the work box;
- F5: the CLI holds every public block resident, an unmeasured cost.

F6–F9 are Info.

## 2. Registration — CORRECT

- **D55 against D12a, in both directions.**
  - CS-7 (`run.rs:310-365`) names no D55 string, so `RunShape::new` refuses one (tested for all twelve).
  - `ForkRun::new` refuses any profile CS-7 would admit (`run_fork.rs:501-503`).
  - A D55 transcript is `tagged_transcript(base block shape, D55 string)` (693). It differs from D12a's at the
    constructor.
  - On disk, the file names, magics, counted lengths and bindings all differ. The probe
    `d12a_verifier_on_d55` is refused by name, as are the builder's six CLI steps.
- **One base against another.**
  - The string is a pure function of the base (485-496). Different bases have different constructor inputs.
  - Different bases also have different shapes and statements.
  - A receipt under the same statement's test-only identity is refused by the chain even with every binding
    and tag rewritten (`run_fork_tests.rs:813-862`).
- **Ineligible bases are refused.** Pre-R13 runs get the production refusal by name (283-286). Token and
  classifier runs are refused first (482-484). W16 / W16R2 run identities exist only under `#[cfg(test)]` in
  `registered_block_shape` (`run.rs:324-330`), so a release build cannot even form their `RunStatement`.
- **The door checks exactly marker + base.**
  - The registry entry must equal `hashline-zk-mr1/` ‖ `D55_REGISTERED_MARKER` ‖ the base's tail (489-492).
  - That every base is an R13 blocks-only run, each exactly once, is asserted by
    `d60_every_registered_d55_profile_is_the_marker_and_its_base`. The door does not check this itself.
    That is acceptable for a source-controlled table.
- **Keys and domains.**
  - Each string hashes under its base block shape's four keys, and s24 asserts the live key for all twelve.
  - Constructor inputs are 107, 125 and 129 bytes, at least 3 bytes from every absorb.
  - **The census is complete.** s25 W-2 measures each registered profile at L = 1, 22 and 32
    (`logs/chain/g_scans.log`: "the 12 registered D55 run profiles among them").
  - s33 J-7a has 127 profiles: 100 from the registry (the twelve D55 literals included) and 27 test-only fork
    domains. Its thinnest point is 14 forced-NUL positions, at the D55 8B-DD string.
  - I checked `w2_pairs.py` and `logs/w2_registered_d55_pairs.txt`. The only equal-length pair not in the base
    table is `pb-fork-s0` / `pb-fork-s1` (66 B). The arithmetic is 32 + 8 + 10 + 8 + 8 for both, and the two
    are separated by the label byte at offset 49.

## 3. Reading a receipt in production — AS STRICT AS D12a, with one platform gap (F4)

- **Directory.** `read_fork_receipt` (1491-1523) accepts exactly `L + 2` names, with `L` the verifier's own,
  plus one `statement` DIRECTORY. Anything else is refused before a byte is read. This is `segment_paths`'s
  rule.
- **Each frame** goes through `read_frame_bounded` (1452-1482), in this order:
  1. the counted length, from the verifier's statement and at most the wire ceiling;
  2. `symlink_metadata`: a regular file only;
  3. the metadata length must equal the counted length;
  4. open, then `fstat` re-checked;
  5. a read capped at `want + 1`.
- **Allocation.** Nothing read from a frame sets an allocation or a loop bound. `decode_head` / `decode_fork` /
  `decode_tail` check the exact length first, and every count comes from the layout.
- **No panic on attacker bytes.**
  - `Reader::take` uses `checked_add`.
  - Field words are canonical-checked and column indices bounded (`wire.rs:204-238`).
  - No `unwrap` or slice index in `run_fork_wire.rs` touches frame bytes.
- **The verifier indexes only after checking.** `rc.forks.len() == l` is checked before indexing (1228),
  `seen.len() == l` before `seen[k + 1]`, and the tail decodes to exactly `L − 1` boundary openings.
- **Probes, release binary:** a FIFO frame, a symlinked frame, a frame 1 B short or long, an extra file, a
  leftover `.partial`, a wrong fork name, and `statement` as a file. Each was refused before any read.
- **The gap: platform flags (F4).** `O_NOFOLLOW | O_NONBLOCK` is set on x86-64 Linux only (1466-1470, copied
  from D12a's reader). On this Mac the window between the lstat and the open is unprotected.

## 4. The CLI — PUBLISHES ONLY AFTER FULL VERIFICATION; N IS BOUNDED AND SCHEDULING-ONLY

- **Order in `stack-verify --d55-workers`.**
  1. The door runs before the directory is read (3331-3334).
  2. `verify_run_with_forks_from_dir` (3349) must return Ok before anything else.
  3. The found `statement.json` must be, byte for byte, the D55 rendering (3382). That rendering names the D55
     string, the base and the construction.
  4. `segments.json` must be the hashes of exactly the verified bytes (3385).
  5. Only then is `statement/` published (3398).
- **What the probes refused.**
  - A D12a rendering beside D55 frames.
  - A changed byte in each of: the fork body, the fork start tag, the fork end tag, the head S0 tag, the tail
    body and the tail S1 tag.
  - For each, the exit was 1 and nothing was published. The refusal came from the chain (`pcs zk: column
    index …`, `<v, c> != combined claim`) or from the tag compare.
- **N.**
  - `d55_workers_of` (2679-2690) admits 1..=64, and both functions clamp to `[1, L]` (1007, 1253).
  - Probes: 0, 65 and `2x` are refused. 1, 3 and 64 give the same verdict.
  - N enters no transcript, frame, statement or file name.
  - Generator domains are per block index `k`, never per worker (958).
  - The verifier joins in block order from its own `seen` (1291-1315). Its first error is chosen by the lowest
    `k`, so both verdict and message are independent of N and of thread timing.

## 5. Concurrency — NO SHARED MUTABLE STATE THAT MATTERS

- **Prover.**
  - Workers share `&ForkCtx` read-only: the `ForkRun`, the blocks, the roots, the NTT tables and the
    boundary-data slices `&[Fp]`.
  - Each builds its own transcript (`fork(S0, k)`) and its own `ZkRng::from_os` inside the worker.
  - Jobs are handed out by a rendezvous channel behind a `Mutex`. The lock is released before `prove_one`.
- **Verifier.** It shares an `AtomicUsize` cursor and read-only inputs only.
- **The Metal context** is used by the prover's commitments only. The verifier is CPU-only: no `gpu::` call is
  on the `verify_core` / `verify_zk_tagged` path. So a device race could cost completeness, never soundness.
- **Process-wide atomics** (`metal_slot::CPU_SLOTS`, `argument::TABLE_KIND_*`, `gpu::declines`) are counters
  for timing and self-reports. Nothing proved or verified branches on them.
- **The L + 1 OS generators** are as the D55 review found them: neither a soundness nor a privacy issue. The
  builder's stats assert L + 1.

## 6. Capture writer — NOTHING ON `not_in_a_capture` IS EXPORTED

- `write_fork_bundle` (`run_capture.rs:4396-4449`) writes:
  - the fork recorder's verifier-view JSON (`run.json` carries `not_in_a_capture`, 3282);
  - the per-fork stage files and `d55_tail.json`;
  - the array store;
  - the receipt frames under `receipt/`. These are public; they are what the verifier reads.
  - a README and the manifest, written last.
- It refuses statement tables that were not export-replayed (4400-4402), and it refuses a test-only identity's
  bundle (4463-4468).
- No prover-side value enters. The only difference from the block writer is that the frames are always
  written, where segments are opt-in. They are public bytes, so this costs size, not privacy.
- **Note:** `run_capture` is `#[cfg(test)]` as a whole (`src/private_block.rs:266-267`). This is the same
  test-only capture surface D12a uses. It is not "a production capture writer" (F6).
- **Not yet done (F3):** the D60 writer test does not run the PG-7 allow-list, or any gate check, on the
  registered R13 bundle it writes.

## 7. Do the controls hit the production verifier, and what is uncontrolled?

- **The controls hit the production verifier at source level.**
  - Every control calls the one `verify_run_with_forks`.
  - In a test build its only extra code is the no-op capture hooks and the hook installation.
  - The four named controls, the same-block swap, the D60 headline and the 13 R13 limb families run under the
    REGISTERED R13-rung string. `unreviewed_prototype()` still yields the registered string for an eligible
    base, and `d60_the_registered_door…` asserts the bindings are equal.
- **The release binary has run only L = 1, N = 1** (the fixture has one layer). See F2.
  - The production-only `cfg(not(test))` arms are compiled in no test.
  - My probes add 22 release-binary outcomes, all as expected, but also at L = 1.
- **Uncontrolled:**
  - D55's own preflight: CS-6, CS-1 and the counts (F1).
  - Any privacy gate on a registered-profile capture, and an independent replay of the registered header (F3).
  - Memory at real geometry (F5).
  - There is no D55 golden. Receipts are OS-random by design, so the only independent pin of the D55
    transcript program is the Python D55 replay gate (F3).
