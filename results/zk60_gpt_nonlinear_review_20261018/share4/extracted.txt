**Yes—your algebraic observation is correct. Our existing softmax implementation already uses it.** The expensive part is proving that the result represents the correctly rounded numerical quotient.

For exact division, assuming \(b\neq0\),

\[
c=a/b\quad\Longleftrightarrow\quad bc=a.
\]

An arithmetic proof can therefore check a multiplication instead of executing a division algorithm. Gnark explicitly uses this principle, with additional nonzero checks where needed. genui{"citation":{"ref":"turn1view0"}}

The distinction is that our softmax outputs are **fixed-point integers**, not exact rational numbers.

Let \(P_i\) be the certified integer exponential weights, and define

\[
D=\sum_jP_j,\qquad Q=2^{32},\qquad
Y_i=\left\lfloor\frac{QP_i}{D}\right\rfloor.
\]

Generally, \(DY_i\neq QP_i\), because we rounded. For example, \(\lfloor10/3\rfloor=3\), but \(3\cdot3=9\).

The correct multiplication-based proof is therefore

\[
\boxed{QP_i=DY_i+R_i,\qquad 0\le R_i<D.}
\]

The multiplication equality is cheap. **Proving the remainder bounds is what makes this considerably more expensive.** Without them, any proposed \(Y_i\) could be accommodated by choosing \(R_i=QP_i-DY_i\). We also need bounds preventing modular wraparound, since the circuit operates over a finite field.

I inspected our source and compiled an isolated audit using the previous configuration: **16,384 outputs, 512 entries per row, three 40-bit exponential factors, and 32-bit probability precision**.

| Cumulative normalization checks | Compiled constraints |
|---|---:|
| Quotient multiplication equations | 32,800 |
| Plus output range checks | 100,556 |
| Plus remainder/slack bounds establishing correct rounding | 525,746 |

These are **constraint counts, not latency measurements**. Approximately 94% of this compiled normalization circuit lies beyond the basic quotient arithmetic. Our frontend uses separate product and equality rows here; the mathematical quotient relation itself can occupy one R1CS row per output.

There is another relevant detail from our exponential work: deferring rounding preserves the product of three 40-bit factors. In this configuration, that produces a **144-bit denominator bound**. Every output then needs bounds on quantities of that width. Avoiding intermediate exponential rounding therefore shifts some cost into normalization.

A report calling this entire operation “division” could reasonably identify it as a bottleneck. Attributing that cost simply to checking \(a/b=c\) would miss the main issue. I could not locate Claude’s particular report, so I have not verified its precise breakdown.

**There is an immediate improvement that preserves our current outputs.** The archive already contains an alternative formulation that computes

\[
R_i=QP_i-DY_i,\qquad H_i=D-1-R_i
\]

as circuit expressions, then range-checks them. This removes redundant witness equalities and tightens the output bound where justified. My fresh compilation gives:

| Full softmax circuit | Constraints |
|---|---:|
| Existing baseline | 674,540 |
| Existing alternative formulation | 608,894 |

That is **9.7% fewer constraints**, with the same specified floor outputs. We should benchmark its runtime before assigning a speedup.

For the much larger optimization, I would examine **moving normalization after the attention weighted sum**. If the consumer only needs

\[
O_k=\sum_i \frac{P_i}{D}V_{ik},
\]

we can first compute \(U_k=\sum_iP_iV_{ik}\), then normalize \(U_k/D\). With integer values and outputs at the same scale, the final floor can again be certified by

\[
U_k=DO_k+T_k,\qquad 0\le T_k<D,
\]

with appropriate signed bounds.

This changes the number of quotient checks from the attention row length \(L\) to the value dimension \(d_v\). For \(L=4096\) and \(d_v=128\), that means **32 times fewer quotient checks**, although it does not imply a 32-fold whole-block speedup.

The qualification matters: this removes intermediate probability rounding, so it generally changes the bitwise output of our current implementation. It deserves a separate accuracy-and-runtime experiment. If we require identical current outputs, the remaining targets are the range checks, redundant constraints, and shared-denominator layout.

Also, the repetition optimization from our other chats transfers only when the **numerator and denominator repeat together**. Repeated exponential values in different rows usually have different normalization results.

The reproducible constraint audit is here: [softmax-division-audit.zip](sandbox:/workspace/scratch/d58e980131f0/softmax-division-audit.zip).
