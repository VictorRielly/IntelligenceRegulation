## 1. In plain words, for Victor

**The two stages now have readers, like the blocks.** The kinds data `D` says, for every check of the run, which claims
it checks. For the 26 blocks lane L43 built it from the verifier's own reader. The two token stages (the input stage and
the verdict stage) run the same slot step under a different head, and the input stage reads each slot at its own row
width; nobody had written their readers. This lane wrote them and PROVED that on an accepted run they return exactly
what the run verifier accumulated.

**The "free Merkle work" is gone.** The top theorem's Merkle event (a forged opened column that verifies) spoke of four
free inputs: the chain, the blocks' cores, the rest of the Merkle work and the rest of the roots. With them free, nothing
could be derived from "the event did not happen". This lane set all four to the run's own: the chain the code uses,
each block's core as read off the receipt, the verifier's column checks of every other opening of the run (the stages',
the boundaries', and the input endpoint's, as the audit asked), and the run's other roots. These are within the bound
the theorem already allows (574,464 queries against 3,800,000; 35 roots). From "the event did not happen" it is now
PROVED that every opened column the verifier accepted is the column extracted from the prover's log.

**Three of the "alive" facts are now proved at every part.** Put together, the openings `A` and `H` and the mask check
`M` of every part (the 26 blocks and both stages) meet their alive facts on any accepted run outside the Merkle event.
The app's top theorem is restated with this: of L43's two acceptance premises, `hMW` is gone and `hopW` keeps only the
closing openings (the boundary a part opens).

**One thing in the model does not match the code (finding L45-2).** Every opening in the Lean run model has `2^14`
message columns. Reading the code: the blocks' and the boundaries' openings do, but the two stages' openings use
`2^12` (the registered tier R1_MVP) and the input endpoint `2^8`. So at the real stages the "alive" premises for `A` and
`H` cannot be met as stated, and the top theorem cannot yet be applied to the app. The fix is in an earlier lane's model
(`RtOpen` needs the message width as a field), which this lane may not edit.

**Not done.** The closing openings' alive facts (the carry between parts is now proved; the rest is not), the slots, the
draws, LogUp, and the doom covers.

## 6. Findings

**L45-1 (Medium; for the coordinator and the cover lanes): stage OUT-C's reader must know the statement's PUBLIC
verdict.** `outcDefine` reads the verdict (`gTab … O.verdict`, `kI O.verdict`), so `M`'s functionals at OUT-C depend on
it, while `rkData`'s readers see only the transcript. The readers here take the verifier as a function `W` of the
transcript prefix and ask `W` (read off the run's transcript) to be the statement's verifier (`hW`). At the real objects
this holds iff the run header absorbs the verdict where `W` reads it; the Lean run header `hdr s` is a free parameter of
`rtRunClassify`. ARGUED.

**L45-2 (High; for the coordinator and the owner of L34's `RtOpen`): the stage openings have `2^12` message columns and
the input endpoint `2^8`; the run model fixes `2^14`.** CONFIRMS L43-1. Read off the code (`token_io.rs`: the only
registered tier `R1_MVP` has `stage_log_n 12`, rate `1/4`, `ep_log_n 8`, rate `1/8`; `stage_in_c.rs`, `classify.rs` use
`tier.stage_log_n` for IN-C and OUT-C's `A`, `H`); the blocks' `A`, `H` (`log_cols 14` at R13 Shieldstral T128) and the
boundaries (`endpoint_log_n = log_cols = 14`) are `2^14`. So `RhOpW` (`hlc : logCols = 14`) is unmeetable at the
stages' `A`, `H` and at the input endpoint; L43's `hopW` at parts `0` and `L + 1` cannot be discharged, and neither L43's
top theorem nor this lane's restatement can be applied to the app until `RtOpen` takes the width as a field. ARGUED
(code reading; the grep lines are in `l45_logn.log`).

**L45-3 (Medium; for the coordinator): L43's block lemmas hide the opening whose extraction they ask.** `rh_blk_opA`,
`rh_blk_opH`, `rh_blk_M` conclude `∃ zo root, RhXOk … zo root → …`; the extraction cannot be supplied from outside, so
this lane re-proved them with the extraction inside (`rx_blk_*`), and wrote its own stage lemmas in an EXPOSED form (the
segment read off the bytes, the root's position). Not wrong; the hidden form is unusable downstream.

**L45-4 (Low; for the coordinator): `EvXR` is hard-wired to 26 blocks.** The theorem asks `Lb ≤ 26`; a run with more
blocks needs `EvXR`'s `n` as a parameter.

**L45-5 (Info): the input endpoint's Merkle tag.** `rxVx` checks every opening under the run's `tag`; the endpoint test
