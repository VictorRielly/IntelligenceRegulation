## What this lane is doing and why

`scripts/zk60_native_joint_view.py` can today assert only the WEAK per-slot
identity of the mask channel (report `ZK60_NATIVE_JOINT_VIEW.md` §3.1):
`mask_eval_s == (fin_s − terminal_polynomial_s) / c_s`, where
`terminal_polynomial_s` is read from the capture as the ALREADY EVALUATED
value `fin − c·mask_eval`. The slot's composition polynomial `def.poly` is a
Rust closure and is not in the capture, so a perturbed terminal is invisible
to that identity. Codex asked for the port rather than a new capture schema:

> port the 23/18 terminal polynomials to the Python diagnostic and compare
> every recomputed value against all four captures; keep the port's slot
> ordering and source pins explicit, with a changed-terminal negative
> control.

The STRONG check is then the verifier's own final equation, in the masked form
it is actually checked in (`private_block/argument.rs:340`,
`private_attention/argument.rs:326`):

    fin_s == c_s · mask_eval_s + poly_s(vals_s)

with `vals_s` built exactly as the verifier builds it:
`sel·eq_point(point, rho_main[start..])` for an eq table,
`sel·eval_mle_ext(values, rho_main)` for a public table, the published
terminal for a private table, and `sel = Π_e (1 − e)` over the extension
challenges.

**This is a consistency check of the verifier's view. It is NOT a privacy
property, and D8 / D11 are untouched.**

## What the captures already carry (checked, 2026-09-19)

Everything the strong check needs is in the schema-3 capture; **no new capture
field is required**:

- per slot: `definition_challenges` (every Fp2 draw of `define`, in draw
  order), `c`, `scalar`, `claimed_sum`, `rho` (main ‖ extension), `rounds`,
  `sumcheck_final`, `mask_eval`, `terminal_polynomial`, `terminals`, `hosted`;
- per table, in the Rust push order: `eq` with its `point` and `start`,
  `public` with its full `2^main` `values`, `private` with role/claim index;
- top level: `logup_challenges` = (beta, gamma, alpha) in draw order, from
  which `g_u8 = gamma·133`, `g_exp = gamma·129`, `g_act = gamma·134`
  (`tables_attn.rs` TAG_U8 / TAG_EXP / TAG_ACT).

The one cross-slot value a closure captures is `pts.lam_z`, drawn in `SC_RS`
and read again by `SC_SZC`'s closure; it is `definition_challenges[6]` of the
`SC_RS` slot of the same capture.
