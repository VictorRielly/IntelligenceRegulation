## 1. In plain words, for Victor

**What was asked.** The app's top theorem still assumed six "alive" facts: on an accepted run, every sumcheck slot,
every define draw of the four relation schedules, and every LogUp run ends "alive" (it was not fooled), whenever no
earlier check of the order was fooled. Each of these is a statement about the run's ONE transcript, the whole classify
run of 28 parts.

**What this lane did.**
1. It took the six facts apart into their single sub-protocols, part by part (PROVED for any kinds data).
2. It proved that on an accepted run, the run's transcript, read at block `k`, IS that block's own verifier trace (the
   header being everything the run did before the block, plus the block's five-absorb frame), followed by the rest of
   the run. So everything already proved about one block on its own trace carries to the run.
3. With that, at each of the 26 blocks, the six facts are PROVED to follow from three block-level facts at the block's
   reading of the run: every slot's final check holds on the committed data (`RaTermAt`), every define draw's
   polynomial is zero at the point it drew (`RaDefAt`), and LogUp's helpers exist at its challenges (`RaLkAt`). These
   are exactly the facts the block-level statements (lanes L16, L36, L47) already derive from the block's algebra.
4. The top theorem is restated with the six assumptions replaced by those block-level facts at the 26 blocks and by the
   two stage parts' facts.

**What is still open.** The block-level facts at the app's R13 blocks (they need the R13 slot polynomials and the
hosts' identities, lane L49's area, and the run-level "the opened claims are true" link); the two stages' parts (they
are trivially met if the stage parts carry no slots or draws, and need the stages' own reading otherwise: finding
L50-1); the closing openings of parts `1` on; OUT-C's verdict off the header (`hW`).

**L50-1 (Medium; for the coordinator and lane L51): the stage parts' alive premises depend on what the stage covers
put in the stage parts' lists.** With empty slot, define and LogUp lists at parts `0` and `Lb + 1`, `hsl_stg` …
`hLU_stg` are met trivially. If the stage covers `hdin` / `hdout` / `hdzero` (L51) place stage define draws or LogUp

define polynomial, and nothing earlier in the order is doomed. The two lanes' choices of `base 0`, `base (Lb + 1)` must
be made together. ARGUED.

**L50-2 (Low; for the coordinator): the block parts' slot lists are forced.** `hslB` pins block part `k + 1`'s slots to
L16's schedule at `off (k + 1) + 5`. Any other list makes `hal_slots` unprovable at the real run (its windows would not
be the transcript's slot windows); `ra_blk_acc` proves these windows are the run's. `hD`'s slot conditions hold at the
Shieldstral shape (`ra_shield_slot_conds`, PROVED); whether every one of the 26 layers' `Pk k` has that slot shape is
the block profile's (not checked here).

**L50-3 (Info): the run's transcript at a block is the block's verifier trace.** `ra_blk_acc` is the general form of
L43's `rk_blk_run` reader equality: every block-level lemma stated on the code's trace of `allOps` (L16, L21, L28's
block files) applies at the run with the header `off i + 5` operations long, provided it allows trailing operations
(`ra_slots_alive`, `ra_def_blk`, `ra_lk_blk` are such versions).

**L50-5 (Medium; for the endpoint lane and the coordinator): the run header absorbs the input root INSIDE the
`expected-IO` bytes, not alone.** L48's `rx_inc_opX` / `og_hopX0` take `hInAbs`: some absorb of the run's transcript
before part `0`'s closing window carries EXACTLY the bytes of `s.inRoot`. The code's classifier header absorbs the input
token endpoint's spec AND root together under `expected-IO` (`run_capture.rs` line 3743: "expected-IO (the ONE input
token endpoint spec and root)"); that absorb's bytes are not the root alone, so `hInAbs` cannot be met at the header's
position unless another absorb of the run (e.g. inside stage IN-C) carries the root alone. Which absorb `xPos` should
name must be CHECKED against the code (the bytes of `ExpectedIo::to_bytes` for the classifier, and stage IN-C's
absorbs) before `og_hopX0` is counted as applying to the app. ARGUED from the code's own description; not CHECKED.
