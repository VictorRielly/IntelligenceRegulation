## 1. In plain words, for Victor

**Where we were.** Lane L51 found that the code absorbs your input's commitment root only inside a longer message
(`expected-IO`, 84 bytes: a tag, a digest, then the root), while the Lean model only knew how to find a root that is
absorbed on its own. So the part of the top theorem about the input's opening could not be met. L51 offered two
repairs: A (change the code: absorb the root on its own too) and B (change only the Lean: teach it to read the root out
of the longer message). You have not ruled; B keeps today's bytes, so this lane finished B.

**What this lane did.**
1. It added to the model a second kind of opening, whose committed table is pulled from the prover's work at the root
   read OUT OF `expected-IO`, and proved for it everything the old kind had: the verifier's check of it cannot be
   passed by luck except with the usual small chance, and it reads the prover's work in the stable way the rest of the
   proof needs.
2. Reading the root this second way costs one more "the prover's hash work was unusual" event. Its chance is bounded
   exactly like the existing one. Added to the security budget, the total is **55,852,891 units out of the
   67,108,864 the target allows (83.2 %)**, up from 55,525,211. This is now a theorem, not an estimate.
3. It rebuilt the whole chain of the top theorem (ten theorems, about 2,000 lines, generated by a script from the
   existing ones) with that extra event and with the input's opening of the new kind.
4. At the code's own header (the eight absorbs L51 checked against a real receipt), it PROVED that the input's
   opening passes the check the top theorem asks of it: no premise about where the root is absorbed is left.
5. The top theorem also tests the input commitment a second time (the "column test"). This lane built that test
   FROM the same opening, so the two can no longer disagree, and PROVED fourteen premises about it (its code is the
   endpoint's code, its numbers, its error bounds, and that its second half cannot be fooled when the opening's
   check passed).

**What is left at the input.** The extractor that reads the input's columns back out of the prover's work must also
return each column's salt and Merkle path (`ops`, `hops`, `hcan`, `mk`, `hE`, `hread`, `hdzero`). This lane did not
build it. It found one design constraint for whoever does (finding L52-1): the model's decoders ignore the hash domain
tags, so that extractor must re-encode what it finds and compare, or `hops` cannot hold.

**Nothing found unmeetable.** Every premise this lane introduced is met by the real objects (§5), and none of the
premises it discharged needed an assumption about the code that is not checked.

### 5.3 Deliverable 3 (the extractor's salt and path): NOT done, and what it needs

`ops` must return, for each column `j` of the input commitment, a full Merkle opening (column, salt, path) read out of
the prover's work, and `hops` asks that every opening it returns OPENS against `s.inRoot` FOR EVERY oracle and
adversary. L22's descent (`extractCol`) cannot be extended to that by also collecting the siblings and the leaf's salt:
the model's decoders ignore the hash domain tag (finding L52-1). What the next lane needs, in order:
1. `extractOpen` (tag-checked): descend from the root as `descend` does, but accept a found preimage only if it
   re-encodes to itself (`nodeQ l r = y`, `leafQ x s = y`, `colQ c = y`), collect the siblings bottom-up and the leaf's
   salt; then `Opens` follows deterministically from the log's consistency (`e.2 = G e.1`): `hops`.
2. Its failure event (the tag-checked extraction differs from the opened column) with its bound (L16's `ExtBad`
   argument, as `extract_of_opens`), replacing or joining `ebEvIn`; then `Xx`, `Ux` read from it, `hread` by
   definition (on an accepted run the header reads `s.inRoot` at position `1`: `ab_rdIn_at1`), and `hBal`'s `hin` as
   `eb_xB_alive` proves it now.
3. `hcan` (the extracted entries are canonical: `colDec` must reject non-canonical bytes, or `ops` must), `mk` (the

4. `hdzero`: stage IN-C's `SIC_IO` zero-check as a part-`0` squeeze run (L46 §5 item 4; with L53's stage lists).

## 6. Findings

**L52-1 (Medium; for the endpoint extractor's lane and the coordinator): an endpoint extractor built on L22's descent
cannot meet `hops`.** The run's Merkle encodings decode a query's bytes without looking at its domain tag
(`merkleEncV`, ExtractInstW16.lean:45-47, and `merkleEncB`, ExecMerkle.lean:206-208: `nodeDec q = leafDec q =
splitDig q.2.1`; `colDec` reads `q.2.1`). The descent `extractCol` finds the first logged query whose answer is the
current digest and decodes it as a node whatever its tag. An extractor that returns (column, salt, path) from that
descent can return an opening that does not climb to the root under the verifier's tagged queries, for an adversary
whose logged leaf (or column) query answers equal a node's: `hops` is stated for every adversary and oracle, so it
fails. Repair (no code change, a Lean definition): the tag-checked `extractOpen` of §5.3 item 1, whose `Opens` is
deterministic. ARGUED (reading the two encodings and `extractCol`); not a protocol issue (the verifier's queries are
tagged).

**L52-2 (Info; for the coordinator): the top theorem's chain is now generic in one more extraction event.**
`RunEpBChain.lean` takes a further event `Ey` with its bound `εy ≤ u126 q cy` and pays it in the gate
(`55,525,211 + cy ≤ 2^26`). Repair A's restatement, or any later event, can reuse it unchanged.

**L52-3 (Info; for lane L53 and the coordinator): what this lane assumed about part `0`'s lists.** Nothing about the
stage sub-protocols: `ebData` takes part `0`'s slot, define and LogUp lists from `base 0` through L43's `rkData`
unchanged (`ebData_same`), and the top theorem keeps L50's `hX_stg` and L53's `hdin`, `hdout` as they were. This lane
fixes ONLY part `0`'s closing opening: its geometry and claim count (`hgX0`, `hnX0`) and its matrix reader
(`abRdIn` at position `1`, by `ebData`).

**L52-4 (Low; for the coordinator): `hRr` names a fact the statement left implicit.** The column test's rows are the
input commitment's `Rr` and the opening's are the stage contract's `Iin.pX.rows`. Building `T` from the opening needs
them equal. Both are the one endpoint commitment's rows (`6`, CHECKED by L48); a lane that ties `Iin` to
`epTokenCommit` can prove it.
