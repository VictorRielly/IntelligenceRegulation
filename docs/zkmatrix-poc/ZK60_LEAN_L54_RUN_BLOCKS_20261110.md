## 1. In plain words, for Victor

**What was asked.** Gap GA-3: the security of each of the 26 blocks is assumed at the run level; no top theorem uses a
block theorem. Lane L49 proved each Shieldstral layer's block statement with no block-level assumption. This lane was
to connect the blocks to the run, so that the top theorem's per-block assumptions come from the block results.

**What is now proved.**
1. **The run-level link "the openings check what the blocks claim" (deliverable 1).** In the whole classify run, every
   block hands claims about its committed data to three openings: its own `A` and `H` openings, its closing opening
   (for its input boundary) and the NEXT part's closing opening (for its output boundary). The lane proved: on an
   accepted run, outside the run's extraction failure, if none of the openings' first checks and none of the mask
   checks "started from a false claim", then for every block every claim it handed on is TRUE of the data the proof
   extracts from the prover, and every mask functional is true. This holds at every way of reading the block off the
   run's transcript (the lane proved that all such readings agree with the run verifier's own reading).
2. **The block slots' "alive" assumption is gone (deliverables 2 and 4).** The top theorem assumed, for each block,
   that every sumcheck slot's final value is the slot polynomial's value at its point. That now follows from item 1
   and lane L16's slot lemma. What is left in its place is a statement about the slot polynomials themselves ("each
   is the masked slot polynomial over the extracted data") and that each block's verifier is defined by a slot
   program (which makes its arithmetic canonical).
3. **Every one of the 26 layers has the one Shieldstral slot shape** (lane L50's open question L50-2): PROVED from
   lane L49's per-layer program check.

**What this lane found (finding L54-1, High).** The kinds data's slot polynomials (`Fsl`) only see the block's `A`,
`M`, `H` commitments. Two slots of every R13 block (`SC_IO_IN`, `SC_IO_OUT`) read the run's boundary commitments (the
block's input and output planes as the previous and next parts commit them). Their true polynomial cannot be written
with that type, so the slots' assumption (old or new form) cannot be met at those two slots as the model stands. The
repair is a change to the Lean model only (give the slot polynomial the boundary commitments' extracted tables, read at
the roots the run's header absorbs); no code change. Lane L49's block statement models the same boundary data the same
way (`XE`), so the same repair serves it.

**What is not done.** The define draws' and LogUp's alive assumptions (`RaDefAt`, `RaLkAt`) and the per-block cover
`hblk` from L49's block result: §5 says precisely what each needs.

**L54-1 (High; for the coordinator, the next run-wiring lane and lane L49's successor): the block slots' polynomial
type cannot express the two boundary slots.** The kinds data fixes each block part's slots to L16's
`blockSchedX (Pk k) … (Fsl k)` (`hslB`), whose polynomial `Fsl k : Cuts3 → RootsO → j → Seen → point → K` receives the
log cut at the block's `A`, `M`, `H` roots and those roots only. R13's `SC_IO_IN` and `SC_IO_OUT`
(`BlockR13Prog.lean` line 657: tables `[eq, aPlane x / x2, epTab .inp / .out]`) read the boundary commitments' tables,
whose claims the closing openings of parts `k + 1` and `k + 2` check at roots that are not in `RootsO`. The masked slot
polynomial of these two slots over the extracted data is therefore not of `Fsl`'s type, and `hsl_ev` (this lane) and
`hsl_blk` (L50, which `hsl_ev` implies) are not met by it at those two slots of each of the 26 blocks. Nor, ARGUED, by
any other function of that type for every adversary and oracle: an adversary may absorb its `A`, `M`, `H` roots in
early queries (its cuts then end before the boundary trees are built, outside the extraction event since those trees
are extracted at their own roots), so two runs can show `Fsl` the same arguments while their boundary tables, and so
the slots' true values, differ. ARGUED (reading the program and the types; the run-level link itself is PROVED). Repair (Lean only): §5.1. Lane L49's block statement
has the same shape (`XE`, `hcsE`), so the repair serves both.

**L54-2 (Medium; for the coordinator): the top theorem does not tie block `k`'s verifier to layer `k`.** `Pk` is a free
object; L49's block results hold for a verifier `P` with `IsShieldR13 P` and `P.define = defineS (progR13 (cfgShieldR13
Ly) …) (pubsR13L …)` at layer `Ly`. Using them at the run needs a premise `∀ k < Lb, IsShieldR13 (Pk k) … ∧ (Pk k).define
= defineS (progR13 (cfgShieldR13 (layer k)) …) …` (met by the real objects as L49's `hdef`: CHECKED at the rung, ARGUED
at Shieldstral). This lane needed only its weakest part (`hdefS`).

**L54-3 (Info): the "every reading" quantifier of L50's alive facts costs nothing.** `RaTermAt`, `RaDefAt`, `RaLkAt`
quantify over every reading of the block on the run's transcript. `wr_acc_rd` PROVES every such reading has the run
reader's accumulator (the header length and the core's shape fix the slot loop's end), so a reading-free fact (the
run's own) transfers to all of them.

**L54-4 (Info, method): the run-level `hsem` is deterministic.** `wr_hsem` needs no acceptance: only the openings' and
`M`'s acceptance facts at their windows (`RhOpW`, `RhMW`) and "no doomed `opA`, `M` entrant". Acceptance enters only
to obtain those facts (`rx_parts_AHG`, `rx_parts_MG`, `hopX1`).
