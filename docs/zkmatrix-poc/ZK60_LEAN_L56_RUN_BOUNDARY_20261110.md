## 1. In plain words, for Victor

**The problem (finding L54-1).** Each of the 26 blocks runs 23 sumcheck "slots". The top theorem assumed that, for
every slot, its last value equals the slot's polynomial evaluated over the data the proof extracts from the prover.
Lane L54 found that the Lean type of that polynomial could only look at three of the block's own commitments (`A`, `M`,
`H`). Two slots of every block (`SC_IO_IN`, `SC_IO_OUT`) read the run's BOUNDARY commitments: the block's input plane
(committed by the part before) and its output plane (committed in the block's own frame). Their true polynomial could
not be written with that type, so the assumption could not be met at the real system: the tenth such premise.

**The repair (this lane).** The slot polynomial now also receives, for every position of the run's transcript before
the block's own roots, the root absorbed there and the prover's log cut at it. The two boundary roots are among them:
the code absorbs block `k`'s input boundary root as the third absorb of the previous part's frame (run position
`off k + 2`) and its output boundary root as the third absorb of its own frame (`off (k + 1) + 2`). The new schedule
still reads the prover's log only through cuts at roots the transcript shows (PROVED), so the knowledge argument's
"frozen once logged" property is unchanged; its slots have the same shapes as before, so the run's windows and degrees
are unchanged (PROVED).

**What is now proved.**
1. The run-level "slots alive" fact for the new schedule (lane L50's `ra_hal_sl`, re-proved: `ra_hal_slB`).
2. The top theorem's chain (lane L52's three theorems and lane L54's) restated with the new schedule; the slots' alive
   premise is still PROVED from the run-level link L54 built.
3. **The premise left in its place is about data the new type sees.** At every reading of block `k`, every table the
   slots' interface reads (the `A`, `H`, `M` tables and the two boundary tables) is a function of the slot polynomial's
   own arguments (PROVED: `bnd_args_cs`, `bnd_args_ms`). So the premise reduces to a property of the polynomial as a
   function (`bnd_slotEval_args`), which the masked slot polynomial over those tables has by construction (ARGUED, as
   for every other slot). Lane L54-1's obstruction is gone.
4. The block's boundary claims are about exactly the tables the run's closing openings check: same root, same log cut
   (PROVED: `wrCs_eq_B`, given that the closing openings read their roots at the code's positions, `hgXB`).

**Checked against the code.** On a real classifier receipt with two blocks (the development rung), a test-only replay
of the production verifier records each part's frame in order and the root each closing opening is verified against:
every frame has the boundary root third; block `k`'s closing opening opens the root the previous part's frame absorbed
third; stage OUT-C opens the last block's. Five wrong variants per block (boundary root moved to second, the block's
own root, the previous part's `A` root, the block's input claims left out, its output claims put in their place) and
one at stage OUT-C are each refused by the production code. A source check confirms the frame order, the carry of the
roots, and that block `k` is verified at layer record `k`'s calibration and digest, in order.

**Block `k` is layer `k` (finding L54-2).** The top theorem did not say which verifier block `k` uses. A new premise
`hPk` says: the run's block `k` carries layer `k`'s calibration from the app's export, and its verifier is the code's
Shieldstral R13 verifier at that layer with that block's public data (everything lane L49's block theorem asks of a
verifier). The code does exactly this (CHECKED in the source: stage `k`'s calibration and digest are layer record
`k`'s); the R13 verifier facts are lane L49's (CHECKED at the rung, ARGUED at Shieldstral).

**What is not done.** The IO slots' own polynomial and start claim (`DIO`, `hIO`, finding L46-3) and the use of lane
L49's block theorem for `hblk` (§5).
