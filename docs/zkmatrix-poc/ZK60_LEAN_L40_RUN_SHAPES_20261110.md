## 1. In plain words, for Victor

**What was wrong (gap audit finding GB-2).** The Lean model of the whole classifier run gave all 26 blocks ONE shape.
A block's shape holds its rounding shifts and its two norm constants. The real Shieldstral model has a different
calibration in every layer. So the Lean model could not describe the model the app runs, and no top gate theorem could
be applied to the app.

**What this lane did.**
1. **A run model where every block has its own shape** (PROVED). The blocks must agree on two numbers only: the token
   count `T` and the width `d`. The reason: block `k + 1` reads exactly the plane block `k` writes, a `T × d` plane, and
   the two stages read and write that same plane. Everything else (heads, hidden width, norm constants, every shift,
   the softmax window, the activation groups) belongs to one block. The approved statement's lemma `CircuitIff` is
   PROVED for the new model. The old model is exactly the case "all shapes equal": the two models are PROVED equal
   there, and L2's theorems are re-derived from the new ones. Nothing proved before is lost.
2. **The app's real model IS an instance** (PROVED and CHECKED). The 26 layer calibrations are read from the app's own
   verifier export (its `profile.json` hashes to the app's pinned `PROFILE_SHA`). All 26 shapes are PROVED valid, and
   PROVED to meet the R13 layout's windows. The new finding: the layers differ in MORE than their shifts. The norm
   constants differ in every layer, so there are 26 distinct calibrations, not 17. Lean now PROVES that no single shape
   fits all 26 blocks. The export's public tables (gains, multipliers, rotary tables, softmax and activation tables)
   are CHECKED to be in their classes, and so are the two stages' tables: 2,222 checks, 0 failed. The one part NOT
   checked is the weights' int8 class: the weights are pinned by hash in the export, but their bytes are not in the
   repository.
3. **The protocol and the top gates, re-stated for the new model** (PROVED). The verifier is the same object. The old
   gates' proofs used the shared shape in only three places, all at the model level: chaining the blocks into the
   run, the run's link to the model, and `CircuitIff`. Those three are re-proved for a shape per block. Everything else
   is a mechanical re-indexing, generated by a script from the old statements. The top gate `rt_productionReady_r13`
   now has a version, `rt_productionReady_r13P`, that can be applied at the app's real model. The block-shape and
   block-count obligations are PROVED there (`shield_classifyOpenP`).
4. **The approved model now runs** (GB-8; PROVED and CHECKED). The approved model is written with a non-constructive
   choice, so it could not be executed. This lane gives an executable twin and PROVES it equal to the approved model,
   for the block, the run and the whole classifier. The twin was run on the committed R13 test block at both number
   stacks. Every intermediate plane equals the Rust witness builder's words and the independent oracle's (§6). The
   classifier's last stage, run on every row of the block's output, accepts and refuses the same rows as the Rust code
   and gives the same verdicts. Single changes to a weight, a shift, a norm constant, the input, the exp table, the
   activation table or a gain are all caught. 69,018 checks, 0 failed.

**What this does not do.**
- The top gate's other premises are unchanged. That includes L34's stage-contract defect GA-1, which lane L39 is
  repairing. After L39 merges, re-running `l40_mk_gate.py` regenerates the per-block gate file.
- The weights' int8 class at the real model stays a premise (D62).
- No trained golden (8B, Shieldstral, TinyLlama) has been compared. Each needs its weights and a Rust trace (§4.4).

## 5. Findings

- **L40-1 (High; for the coordinator and Victor). GB-2 is real and larger than the audit said.** The audit counted 17
  shift sets. The norm constants `cn_a`, `cn_m` are `BlockShape` fields too, and they differ in EVERY layer: 26 distinct
  calibrations (PROVED `shield_cals_distinct`; the audit's argument that differences might fold into multipliers cannot
  apply to norm constants, which have no multiplier). Fixed at the model by this lane: the per-block model, the app as
  its instance, and the gates re-indexed. Every earlier gate theorem is still stated at L2's one-shape model; only the
  `…P` versions apply to the app.
- **L40-2 (Info; for the lanes using `R13Windows` at the app).** At the app, the R13 windows hold at `ls = 1`
  (`R13Windows … 1`: two softmax limbs, `wrho_s = 16`), not at `ls = 2`. L17's docstring of `shield_layers_accepted` says
  "at `ls = 2`, `wrho ≤ 16`", mixing the plane count's convention (`aPlanes true 2`: the limb count) with
  `R13Windows`'s (the limb count minus one); `R13Windows … 2` is FALSE at every layer (PROVED `shield_not_r13Windows2`).
  No theorem was wrong; a lane that instantiates `blockSat_of_slots_r13` at the app must use `ls = 1`.
- **L40-3 (Low; for the Lean doc owners).** `BlockShape.Valid`'s doc (CircuitBlock.lean:131) says `ceps = 1` at every
  registered shape. The app's export has `norm_ceps = 2439`, the fixture `123` (CHECKED). The class allows it
  (`1 ≤ ceps ≤ 2^24`), so no proof is affected; the comment is stale.
- **L40-4 (Medium; for Victor and the coordinator).** At the real model, the only unchecked part of every block's
  public data is the weights' int8 class (D62). It is a 26 × 7-file scan for anyone holding the pinned weights; the
  rest of `BlockPublic.Valid` is CHECKED on the export.
- **L40-5 (Info; for the coordinator).** The one-shape assumption was used by the gates' proofs only at the model level
  (three places, §2.3). This is ARGUED from the sources and confirmed by the generated file compiling with the
  sources' proofs unchanged.
- **L40-6 (Medium; for the coordinator, with L39).** `rt_productionReady_r13P` inherits every premise and finding of
  `rt_productionReady_r13`, including GA-1. It must be regenerated after L39's repair merges (§4.3).
- **L40-7 (Low; for the checkers and the next lane).** L2's model was noncomputable only through `liftO`'s choice and
  `NormOK`'s missing decision procedure. Two performance traps, both avoided in the shipped twin (still PROVED equal):
  a table built inside a definition whose own type is a function type is rebuilt at every read (the first version had
  not finished the fixture after ten minutes); and a softmax row's maximum and total, recomputed per column, cost
  `O(T³)` per row. Built by the caller and shared per row, the whole fixture check runs in about 12 seconds under
  `lean --run`.
