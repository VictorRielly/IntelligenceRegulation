## 1. In plain words, for Victor

**Why this lane.** This weekend's lanes proved the block-level pieces for the W16R2 profile. Lane A25 then found that the
real Shieldstral model cannot run at W16R2: each layer's calibration moves W16R2's plane list. The media app's
classifier runs **R13** blocks, so R13 is the realistic production candidate. This lane makes the block-level results
hold for R13.

**What R13 is, next to W16R2.** Both compute the same integer block (the same `BlockSat`, the same proved
`block_circuitIff`). They differ in how they range-check the integers:
- R13 splits every 16-bit word into two committed bytes, with a clause that ties the word to its bytes, and looks every
  byte up in ONE byte table. A shift only changes one coefficient of one lookup, so **the plane list never moves**.
- W16R2 looks each 16-bit word up directly, in a set of range tables whose widths come from the shifts. That is why
  the real model's per-layer shifts move it.
- R13 encodes its commitments at code rate 1/4 with 256 opened columns; W16R2 at rate 1/2 with 280. The mask
  commitment `M` is the same in both.

**What is now proved for R13.**
1. **The layout map** (`blockSat_of_slots_r13`): the R13 slots' relations and the byte-table lookups give the block's
   constraint system at the model's positions, so (with `block_circuitIff`) **an R13 block's output is the integer
   block's output** (`r13_block_output`). The proof reduces R13 to L11's W16R2 theorem: the R13 data, read as W16 data,
   satisfies W16's relations and W16's lookups. No W16R2 theorem had to be reopened.
2. **The real model's calibration is admitted at R13, and the plane list is fixed** (`ShapeR13.lean`): all 26 real
   Shieldstral layer calibrations (A25's census) pass the code's R13 calibration check, which puts every shift in its
   limb window; the plane counts are functions of the stack and the softmax limb count only (A 107, H 53 for
   Shieldstral T128, exactly what the census measured at every stage).
3. **The openings at R13's geometry** (`OpeningR13.lean`): L10's executable opening verifier at rate 1/4, 256 columns,
   2^16 encoded columns, PROVED to accept exactly when every check holds, and to move the transcript as L9's block
   verifier expects. **Binding at the target** for R13's commitments. `M` and its `2^-106` Fiat–Shamir bound carry over
   unchanged: `M` reads no shape field.
4. **One R13 opening is sound at about 2^-111** (`opening_sound_r13`), from the unique-decoding lemma (which holds at
   any rate). The code prices an R13 opening by the older δ/3 count, about 2^-105.6; the proved figure is better.
5. **The block's sumcheck Fiat–Shamir bound on the real R13 schedules**: at most 2^-61, both at the R13 rung and at the
   Shieldstral T128 R13 block (`rung_block_fs_sound`, `shield_block_fs_sound`).
6. **The frame the classifier run actually carries** (`decodeSegment`): the D12a run segment, in executable Lean, PROVED
   to have one encoding.
7. **The slot list at R13** (`SlotR13.lean`): the same 23 slots and degrees as W16R2; only the batching draws of six
   zero-checks differ, and they do not change the numerator budget.

**Checked against real R13 receipts** (TESTED, §6): a real R13 rung block proved by the production prover (the block
verifier's every challenge, the slot arithmetic, the `M`, `A`, `H` openings honest and tampered), and a real D12a
segment of a one-stage R13 run (decoded, re-encoded byte for byte, fourteen single changes refused exactly as the
code refuses them). Every check is paired with a negative control.

**What this does not do.** The same items as for W16R2 stay open at R13: the slots' polynomials as Lean functions
(today checked against the code, not proved), the knowledge composition (lane L16), the run level (the D12a run's
stage steps beyond the block core, the boundary and endpoint openings, the classifier stages), and the `Protocol`
instance (lane L18). §7 lists them.

## 5. Findings

No finding is a mismatch between the code and the approved statements; none weakens a statement or a target.

**L17-1 (Info): R13 needs no new circuit theorem.** R13 and W16R2 arithmetize the same integer block; R13's relations
are W16R2's with byte-limb sums in place of 16-bit limb pairs, plus thirteen decomposition clauses (seven words on
`Dom::D`, three on `Dom::Q`, three on `Dom::Kv`) and three more on `Dom::F` / `Dom::S` (`U`, `H`, `P`). PROVED by reduction
(`blockSat_of_slots_r13` from L11's `blockSat_of_slots`).

**L17-2 (Low, latent; the R13 face of L11-1): the SiLU product remainder's limb count is fixed by the stack, not by the
shift it guards.** CODE: `AccuracyIds::new` gives `RH` two limbs at LowH24 (three at LOW) and `lookups` emits no pin for
it (`bytes(Limbs::Rh, None)`, accuracy_layout.rs:90, 261), so the remainder is range-checked to 16 bits whatever
`folds().product.shift` is; the product clause uses that shift (argument_accuracy.rs:110, 116). They agree today only
through the fold (`accuracy_public.rs` asserts the shifts `(24, 16)`). `R13Windows.prod` (`S.sprod = 16`) states the
requirement. Suggested, as for L11-1: derive the limb count and a pin from the fold's shift.

**L17-3 (Info): the plane list is shift-independent at R13, and the real model is admitted.** PROVED
(`ShapeR13.lean`): the plane counts take no shift; all 26 real layer calibrations pass `derive` at LowH24 with their
gates in `17..24`. This is the formal side of A25's census and of A25's route (c), "R13".

**L17-4 (Info, a margin): the code prices an R13 opening by the δ/3 count; the proved bound is about 64 bits better in
its column term.** CODE: `Shape::column_regime` is `GeneralCode` at every non-W16R2 profile (shape.rs:849-856), whose
column term at R13 is `((2N + K')/(3N))^256 ≈ 2^-105.61`. PROVED: the unique-decoding lemma `opening_sound_rs_half`
holds at any rate; at R13's `N = 2^16`, `K' = 16,640`, `e = 24,448` it gives `≤ 2^-172` for the column term and
`2^16/p² ≤ 2^-111` for the field term (`opening_sound_r13`). The code's R13 whole-run figure is therefore conservative;
nothing changes, and a later counter could price R13 at the unique-decoding radius as D59 did for W16R2.

**L17-5 (Info): `M` is identical at R13.** CODE: `M`'s constants are `zk.rs`'s (wire.rs:17-32), never a shape's; the
R13 rung has 23 masks and 34 functionals, as W16R2. L10's theorems apply as stated; the R13 corpus's `M` records are
accepted and refused by L10's `maskField` exactly as by the crate (§6).

**L17-6 (Info): the classifier run's frame is the D12a segment.** CODE: the R13 classifier run profile is a D12a run
(`run.rs:153`, `RunVerifier::step`, run.rs:1390-1544); its segment is the block core plus the run header, the optional
boundary root and the closed commitment's openings. `decodeSegment` mirrors the frame; the stage's other steps
(`pb-run-stage`, `pb-run-block`, the boundary root's absorb, `check_endpoint_opening` and the endpoint / boundary
openings) are not mirrored here (§7). The endpoint openings are regular openings at the block's geometry
(`R13.blkDim`), so `pcsFieldR13` is their verifier once the run level is written.

**L17-7 (Info): a root flip decodes.** TESTED: the segment's `a-root` change is accepted by `decode_segment` (and by
`decodeSegment`): the decoder does not read the roots, the verifier's transcript does. Consistent with the code.

**L17-8 (Info): the corpus block's header is the W16R2 test harness's** (as L9-6): the R13 rung core is proved by the
production `prove_core` under `w16r2_tests`' header; the D12a segment is a real run's (`run::prove_run`).

**L17-9 (Info): the code's slot IR does not transcribe R13's `SC_TAB`.** CODE + TESTED: `slot_ir::build_slot_ir` returns
"the R13 table-helper slot is not transcribed" for slot 19 at the R13 rung (`IRNONE` in the slots corpus); the other 22
slots have IRs. `CheckR13Slots` checks that slot's verify arm (its draws, `c`, the claimed sum, the sumcheck, the
terminal values, `g` and the transcript) with Rust's closure value for `poly(vals)` (`verify-arm-noir`). Its relation
is three LogUp table identities and the pad terms (argument_accuracy.rs:416-444); writing its IR (or the slots' IRs as
Lean functions, §7 item 1) would close it.
