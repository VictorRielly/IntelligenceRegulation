## 1. In plain words, for Victor

**What was asked.** The media app runs the R13 format on Shieldstral-1.0-3B: 26 layers, each with its own calibration.
The security statement of one such block ("the verifier accepts while the committed data breaks the block's equations
with probability at most the target") still rested on assumptions about the block itself: lanes L41, L44 and L47 had
removed them at the W16R2 test rung only. This lane was to remove them at R13: at the R13 rung, and at every one of the
26 Shieldstral layers, with every assumption shown to be met by the real system.

**What is now proved.**
1. **The R13 rung block's statement and every Shieldstral layer's block statement have no block-level assumption left**
   (PROVED: `block_knowledge_r13_rung`, `block_knowledge_r13_shield`). The Shieldstral one is stated for each of the 26
   layers of the app's export at that layer's OWN shape (its shifts, norm constants and activation groups, lane L40),
   not one shared shape.
2. **All six "host" checks of the block** (the norms, the attention products, the softmax, the MLP) are proved to be
   exactly the formulas the algebra needs, once for both formats and all 26 layers.
3. **The lookup side**: every looked-up value is in its table, and LogUp's helper values satisfy their relations and
   their sum, from what the verifier checks. The count of lookups at the app's block is PROVED to fit the bound
   (66,977,792 ≤ 2^26; L47 had only estimated it).
4. **The verifier's public tables are built from the public data and CHECKED against the code by value** on a real R13
   rung receipt (170 checks, 0 failed; all 43 deliberate changes caught). One table the earlier model was missing was
   found and added (finding L49-PUB-1).

**What is left.** Run-level assumptions (as before); four facts about the verifier that its profile does not pin (the
slot kinds of three slots and the LogUp sum claim: CHECKED at the R13 rung, only ARGUED at Shieldstral because no
Shieldstral receipt has been checked); and the layout facts (ARGUED, as at W16R2). Deliverable 4 (checking a real
Shieldstral receipt) is in §5.3.

**Findings that need a decision.** None needs a ruling on the statements. L49-PUB-1 (Medium) and L49-LOOK-1 (Medium)
are below; L49-FZC-1 (Medium, process) concerns the lanes' build script.

## 2. The design: one proof for the rung and for all 26 layers

The R13 rung and the Shieldstral T128 R13 block differ in their axis widths (rung: tokens 5 bits, width 9, groups 3,
in-group 1, head dimension 6, hidden 10; Shieldstral: 7, 12, 3, 2, 7, 14), in the softmax remainders' byte limbs (3
and 2) and in the precision. Every theorem of this lane is generic in the configuration `c : W16Cfg`. What a proof
reads off `c` is a premise structure decided at each configuration: the foundation's `GeoR`, `ShOkR`, `ProfR`, and each
part's own (`TzcCfg`, `DzcCfg`, `QkvCfg`, `SzcCfg`, `FzcCfg`, `HelpCfg`, `LookCfg`, `RelCfg`, `PubCfg`), each PROVED at
`cfgRungR13` and at `cfgShieldR13 L` for every `L ∈ shieldExport` (raw slots evaluated one layer at a time where a
symbolic layer is too costly: findings L49-HELP-1, L49-DZC-2, L49-QKV-1, L49-SZC-1, L49-FZC-2). The integer model's
constants are tied to `c`'s precision by `PrecR c S`, which holds at the rung from `RungS` and at every Shieldstral
layer at the layer's own shape `shieldShape L` by definition (`precR_shield`).

## 6. Findings

No statement of `Statements.lean` changed. No target weakened. No existing Lean file changed.

**L49-1 (Medium; for the coordinator and the R13 lanes; resolved here): R13's `SC_DZC` batches its named clauses in
the code's order, not `r13Cl`'s.** Lane L36's `r13Cl 14 j` lists `SC_DZC`'s 13 clauses as `d0 … d5` then the seven word
decompositions; the code's IR (`slot_ir_accuracy.rs`, transcribed as `r13DzcIr`, `batchB … [4, 5, 7, 9, 11, 13, 14, 15,
16, 18, 20, 22, 23]`) batches them as `d0, d1, wX, wY, wAO, wX1, d2, d3, d4, wYM, wZ, wX2, d5` (CHECKED by sub-agent
`dzc`). An algebra data whose `κ`-th clause is `r13Cl 14 κ` (the W16R2 pattern) would make the host's identity
unprovable. L36's `R13Spec` only asks each relation to be SOME batch entry, so `dtR` follows the code's order through
`clIx`; no statement changes.

**L49-PUB-1 (Medium; for the coordinator and the R13 lookup lanes; resolved here): L47's `restR13` omits `SC_LZC`'s
public table.** R13's raw slot 3 reads exactly one public table at both configurations (`rawSlot3_tabs`), `supp(Dom::L)`
(1 on `x / 2^lt < 9`: 288 ones at the rung, 1,152 at Shieldstral). With `restR13` slot 3 would read `[]`, a different
verifier from the code's. `restR13L` adds it; CHECKED by value at the rung receipt and at the Shieldstral shape.
L49-HELP-3 (Low, resolved): L47's W16R2 `gateLW` (`x / 32 < 9`) is right only at `lt = 5`; `gateLS` is right at both.

**L49-LOOK-1 (Medium; for the coordinator): the R13 profiles do not pin the LogUp sum claim** (as L47-1 at W16R2).
`IsRungR13` / `IsShieldR13` fix the draws, schedule, groups and openings, but not `P.logupSumClaim` nor the slot kinds of
3, 19, 20; the statements take `hls`, `hk3`, `hk19`, `hk20` as named verifier premises. `hls` is CHECKED at the rung
(`logupSumR13` against the code's 108 parts, both corpora) and ARGUED at Shieldstral. Adding these fields to the profile
structures would remove them.

**L49-FZC-1 (Medium, process; for the coordinator and every lane using the L26 / L47 `iter.sh`): a plan's later lines
can be silently skipped.** `iter.sh` runs its steps inside `while read … done < "$PLAN"`, and `lake` inherits that stdin
and can consume the remaining plan lines: in `fzc_iter1` only the first of three `build` lines ran, with no error. Any
later `check` line would be skipped the same way. `iter2.sh` (every command reads `/dev/null`) fixes it; the lane's
final check used it.

**L49-LOOK-3 (Info): L47-4's count is now PROVED**, at 66,977,792 ≤ 2^26 (margin 131,072); the cover needs only `PrecR`.

**L49-TZC-2 (Low, method; for every lane): a `by omega` inside a theorem's statement can pull unrelated section
variables into its signature** (here an explicit `P : BlockParams`), breaking later rewrites; use explicit proof terms.

**Symbolic-layer evaluation (Info; L49-HELP-1, L49-DZC-2, L49-QKV-1, L49-SZC-1, L49-FZC-2, L49-LOOK-2).** For a

layer evaluates in seconds. So the Shieldstral facts are stated for `L ∈ shieldExport` (the 26 real layers), which is
what the statements need. Rewriting to the closed shape `shShieldR13` first makes shape-only facts hold for every `L`.

**L49-PUB-2 (Info):** the foundation's `PubR` matched the code in every slot, table index, draw offset and width.
**L49-PUB-3 (Info):** the rung receipt has no padded token or head slot, so the checker's padding branches are exercised
