the code's order, not `r13Cl`'s.** Lane L36's `r13Cl 14 j` lists `SC_DZC`'s 13 clauses as `d0 … d5` then the seven word
decompositions; the code's IR (`slot_ir_accuracy.rs`, transcribed as `r13DzcIr`, `batchB … [4, 5, 7, 9, 11, 13, 14, 15,

`κ`-th clause is `r13Cl 14 κ` (the W16R2 pattern, `dtW`) would make the host's named identity unprovable at R13. L36's
`R13Spec` only asks each relation to be SOME batch entry, so the lane's `dtR` follows the code's order through `clIx`
(PROVED inverse `clInv`, `clIx_clInv`); no statement changes.
