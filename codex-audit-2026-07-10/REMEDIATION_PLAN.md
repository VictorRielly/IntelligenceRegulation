# Gated remediation plan

## P0 — Restore one honest protocol/status baseline

### 1. Split the lookup milestone into four explicit states

Track independently:

1. unmasked algebra core;
2. E4 commitment landing;
3. masked/ZK engine;
4. FFN integration.

Current status should be `implemented / toy-integrated / not ZK / not
FFN-integrated`. Remove “U-K8 complete” until the original exit passes.

Exit evidence: one generated status file consumed by the README, M4 design,
M5 report, and scale ladder.

### 2. Implement U-K5a-e

Follow the repository's existing design, with these non-negotiable tests:

- exact histogram recovery succeeds against the deliberately unmasked engine;
- the same recovery fails against engine-scale masked transcripts;
- two proofs that reuse a mask reproduce the leak, and the public API refuses
  reuse;
- G/unpinned and blinder-after-alpha attacks accept in deliberately broken
  variants and reject under shipped ordering;
- all E3-N1..N5 and E4-N1/N2 tests still pass under masking;
- rank/guard checks run at the frozen production shapes;
- abort/restart logic cannot grind alpha, masks, or psi.

Exit evidence: Rust implementation, `#[test]` coverage, full transcript byte
count, measured 1T/parallel deltas, and independent proof review.

### 3. Complete the original U-K6/U-K8 integration

Build an actual chain:

```text
range-proved int8 X
    -> committed masked LogUp-GKR proves Y = SiLU(X)
    -> E4 pins the same commitments
    -> E1/E2 slot link/repack
    -> committed gate o up Hadamard consumes Y
```

Required negatives:

- out-of-range X with a matching residue;
- valid X with wrong Y;
- correct table pair but different committed tensor;
- malicious slot junk with correct constants;
- swapped instance, table digest, tensor orientation, or model spec;
- missing downstream operation from the manifest.

Run first at small size, then at the actual per-layer FFN instance.

### 4. Close integer exactness and statement validation

- Move q31/q46 selection and non-wrap bounds into statement derivation.
- Prove model-weight ranges or define a commitment discipline with an equally
  explicit security argument.
- Add a canonical quantization header: widths, signedness, scale, rounding,
  clamp/overflow behavior, and table digest.
- Validate operation IDs, shapes, orientations, visibility, DAG completeness,
  and every proof-object reference before cryptographic verification.
- Reject unknown versions and duplicate/missing objects.

Exit evidence: a verifier process accepts only serialized statement+proof
bytes and has no witness-side state.

### 5. Correct the performance ledger

- Rename M5 to a commitment-stream benchmark.
- Rename lookup-bench to an unmasked single-thread core benchmark.
- Mark imported 8.74x lookup scaling as assumed, or remove it.
- Define “GPU 20x” once or, preferably, delete it in favor of kernel-specific
  rows.
- Collapse 9.4e9 versus 1.33e10 into one statement-generated pass inventory.
- Separate measured, measured-at-rate, projected-parallel, and assumed-GPU
  columns mechanically.

Exit evidence: a machine-readable benchmark artifact generated by the code,
including commit hash and hardware fingerprint.

## P1 — Make the code GPU-ready without changing semantics

### 6. Create a library and typed backend boundary

Move core types and verification from the monolithic binary into a library.
Suggested boundaries:

- `CommitBackend`: batched A1/A2 commit and response operations;
- `KBatchBackend`: batched GF(q^16) add/mul/fold/round evaluation;
- `Transcript`: canonical encoding only, backend-independent;
- `LookupProver` and `LookupVerifier`: masked protocol objects, no demo-local
  closures;
- `StatementValidator`: pure, bounded, run before cryptography.

The verifier must not dispatch to an unchecked “fast” path based on untrusted
metadata.

### 7. Replace allocation-heavy K elements

At minimum use `[u64; 16]` for semantic values. For GPU, prefer a documented
structure-of-arrays layout that coalesces coordinate access. Preallocate fold
buffers and reuse them. Make every buffer size derive from a checked statement.

Use a two-pass/checkpointed GKR strategy if necessary: compute roots, then
recompute or stream only the layers required by the current sumcheck. Measure
the compute/memory tradeoff instead of retaining the entire tree by default.

Exit evidence: actual masked `2^23` run with host/device peak memory and no
allocator growth proportional to the number of K elements.

### 8. Freeze exact table and field semantics

- Check in the 256 SiLU integer pairs.
- Freeze field constants, irreducibility argument, coordinate order, and
  canonical byte encoding.
- Add known-answer tests that another implementation can consume.
- Make CPU and GPU reject non-canonical field elements identically.

### 9. Build the untrusted boundary

- Canonical, length-delimited proof and statement formats.
- Checked integer conversions and allocation caps.
- `Result`/false on malformed input; no verifier panics.
- Parser and verifier fuzz targets.
- Cross-version/cross-backend replay rejection.

## P2 — Hardware implementation and evidence

### 10. Commitment kernel first

Implement one exact batched q31 commitment workload. Keep CRS and input chunks
device-resident where possible. Compare every output with schoolbook and A1 CPU
oracles. Include transfer, synchronization, hashing, and output materialization
in end-to-end timing.

### 11. Masked lookup second

Only after U-K5 and the contiguous format are stable. Optimize the actual
degree pattern and aggregate leaf interface. Measure each stage rather than
applying the commitment speedup.

### 12. Integrated ladder

For every rung report:

- p50/p95 over warm and cold runs;
- exact hardware/software versions and power mode;
- host/device peak memory;
- bytes transferred and proof bytes;
- prover total, witness inference, proof-only overhead, and verifier time;
- CPU/GPU output digest equality;
- security/parameter version.

Do not extrapolate to the next rung until the model predicts the current rung
within 2x.

## Release gates

| Gate | Required outcome |
|---|---|
| ZK | Masked lookup engine; recovery and reuse attacks fail; simulator reviewed |
| Soundness | Exact integer chain, E2 wired, malicious wrap/junk/DAG cases reject |
| Statement | Canonical validated model/quantization/operation DAG |
| Scale | Actual `2^23` masked lookup and FFN-shape CE proof fit with headroom |
| GPU correctness | Bit-exact CPU/GPU proofs and all negative tests backend-independent |

| Production security | CSPRNG/sampler, parser/fuzzing, side-channel review, external audit |
