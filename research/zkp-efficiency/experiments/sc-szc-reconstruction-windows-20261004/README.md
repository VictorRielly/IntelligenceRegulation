The candidate reconstructs a current MSB-folded table cell from immutable original inputs and the recorded challenge prefix. It buffers at most `2 * pair_capacity` cells per data table, obtains every original round, and materializes/folds the residual once it fits. Prefix weights use an O(j) DFS stack rather than a 2^j allocation. The independent reference materializes and folds tables. A separately expanded polynomial and original Boolean-cube MLE definition check every sample for n=2/3/4; all finals at n=2/3/4/6 use the direct MLE definition. Shared field arithmetic and synthetic fixture generation are locally authored prior research, not downloaded implementation code.

Fixtures include base/full Goldilocks Fp2 (u²=7)/zero values, padded/unpadded degrees 5/4, three distinct equality groups, short p_ht lifted over trailing score coordinates, one to three limb groups, paired/odd lookup helpers, and capacities 1/3/16 with ragged windows. All 66 zero-factor fallbacks and 528 recoveries in the window schedules use actual computed group claims. Arbitrary host assertions cannot seed recovery; seeding one deliberately changes the first round. Dirty padding remains checked by the polynomial, rather than silently omitted. Fourteen controls cover malformed shapes/capacity, driver order, premature finals, source bit order, short equality lift, source/challenge mutation and host-claim misuse. These are differential controls, not native verifier refusals or honest trained witnesses.

**Negative:** this simple algorithm reads every original data-table cell once per early round and once at the switch. For an illustrative n=23 cube, K=23 data tables and B=4096 pairs, it performs 11 source scans and 1,929,379,840 reconstruction multiplications, plus 188,393 residual-fold multiplications and prefix-weight work. Baseline data-table folding needs 192,937,961 multiplications after a single initial table build. Source reads rise from 192,937,984 to 2,122,317,824. The table buffer bound falls from 3,489,660,928 B (K+3 equality tables) to 3,014,656 B, **excluding sources and other scratch**. Retaining a separate full Fp2 source copy adds 3,087,007,744 B and can erase most of the capacity gain. This is not Blendy's staged algorithm or a lower bound on all streaming methods.

These n/K examples are allocation-free arithmetic scenarios, **not an admitted 8B layout or GPU measurement**. Native private-table construction combines slices, fixed/Rho/Flip coordinate maps and broadcasts; a lazy reader must reproduce that contract. Existing committed A/H data remain live for slots and later openings. Current public-table movement also means a borrowed original public table is still an allocation to account for. The GPU chunked route already omits full A/H codewords; CPU fallback retains them. Historical 7.24B-proxy A/H floors are 5.18/14.23 GiB host and 5.17/14.22 GiB VRAM at T512/T1024, before other payloads. No sumcheck-only count supersedes those tier/lifetime obligations.

**Smaller tested refinement:** grouped rounds already factor the equality values, but native `GroupedEqRounds` still materializes/folds all three equality tables. The prior Python Grouped port stores only points/prefixes and returns the exact original equality finals. Added comparisons pass all 495 samples/516 finals against materialized generic evaluation, including 297 separately expanded original-cube samples. Avoiding only the three equality arrays removes `3 * 2^n * 16` capacity bytes and `3 * (2^n - 1)` ordinary fold multiplies/adds/subtracts. At n=23 that is 402,653,184 B (384 MiB); with illustrative K=23 it is 11.538% of the table capacity. All K data tables still build/fold once, with zero added source rereads. This does not claim an 11.538% parent-memory or runtime reduction.

Native `Vec::truncate` does not free capacity. Thus shrinking logical table lengths alone is not a memory release. The current grouped fold calls truncate without shrink. Avoiding an initial equality allocation is more useful than counting its shrinking length; adding shrink calls has separate realloc/copy costs and cannot reduce the initial peak. [Official contract](https://doc.rust-lang.org/std/vec/struct.Vec.html#method.truncate).
