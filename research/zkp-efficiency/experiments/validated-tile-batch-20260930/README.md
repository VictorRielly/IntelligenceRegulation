while preserving exact requested bytes and rejection of corruption anywhere
in the tensor? Candidate `read_tiles(ref, [(offset, length), ...])` preflights
requests, scans the entire tensor, buffers the requested slices, and returns
only after full SHA-256 equality. It keeps no verified flag across calls.

## Cost accounting and the existing better-memory alternative

For a tensor of S bytes, K independent tile reads hash/read K*S bytes.
A group hashes/reads S, eliminating (K-1)*S scan bytes and K-1 file opens.
It adds O(K) overlap checks per scan chunk and buffers all requested payloads.
Defaults cap 16 requests, each at 1 MiB, and their combined payload at 8 MiB.
Conversion temporarily retains bytearrays and final bytes together: about
18 MiB raw payload/scan scratch at the cap, plus Python allocator overhead.
This is a bounded preparation tradeoff, not zero-cost caching.

Public-config accounting assumes every block tensor is completely tiled
once in 1-MiB requests, grouped eight at a time. Initial file inventory,
config/header checks, outside-stack tensors, quantization, padding/permutation,
upload and all proof work are excluded. No measured caller currently follows
this assumed whole-stack tiling schedule.

| Geometry, raw BF16 stack | Repeated single-tile scans | Eight-tile grouped scans | Existing `read_bytes`, once/tensor |
|---|---:|---:|---:|
| TinyLlama, 22 blocks | 33.9884 GiB | 4.6408 GiB | 1.8049 GiB |
| Llama-3-8B, 32 blocks | 1244.0005 GiB | 155.5005 GiB | 13.0005 GiB |

The counted grouped reduction is 86.35% / 87.50% against repeated tile
scans. **The importer already has `read_bytes`**, which needs one scan per
tensor but holds the full returned tensor. Largest raw tensors here are
22 / 112 MiB, with bytearray-to-bytes conversion temporarily doubling payload.
Where that allocation fits, use the existing interface first; the new method
does not improve its scan count. Grouping only matters to a caller that needs
bounded partial reads. Geometry counts match separately reported stack
parameter totals; an independent explicit request/group enumeration checks
the ceiling-based scan formulas.

## End-to-end limit and falsification

No trained calibration caller or import-phase clock exists. Even deleting
the **entire** tiled-import phase of duration I can save at most I / total
workload time; fewer logical bytes alone do not measure time savings.
If import is startup only, reducing it does not change a resident process's
steady complete-proof slope. For m independent T-position passes,
total time = startup + m*recurring-complete-pass-time; 50/s steady needs
recurring-complete-pass-time / T <= 20 ms, including drain. Actual clocks
and memory peaks are required; no numerical 8B ceiling follows here.

Falsify on any byte/refusal mismatch, partial return before the digest gate,
excess buffering, or no enclosing preparation improvement. If the caller
already uses `read_bytes` or requests one tile per tensor, eliminated scan
work is zero and the candidate is demoted. A native full-stack rate must be
independently verified, and no masks, commitments or private openings are
reused by this proposal.
