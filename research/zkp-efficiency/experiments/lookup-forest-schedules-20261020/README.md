## Result

Each fraction node holds two Fp2 values, 32 bytes. For the 83 original
ordered query columns at 8B T128, plus one 256-leaf global histogram/table,
the exact materialized forest occupies 3170.016 MiB (non-DD), 2954.016 MiB
(DD). The U8 helper data being considered is 420.25 / 390.25 MiB. Neither
set of numbers is a native peak-memory or elapsed-time measurement.

| Reduce all roots, then rebuild one complete column | 128.006 / 128.006 | nearly 2 / 2 | 2 / 2 |

| Retain top 16 depths | 390.016 / 390.016 | 2.870 / 2.885 | 4.664 / 4.664 |

Ratios compare **fraction-tree construction**, not the native helper writer,
whole GKR, complete proving, CPU/GPU time or physical memory traffic. Small
buffers can require much more arithmetic and original-A rereading. At counted
T512, the one-column plan needs 512.006 MiB before proof scratch. The top-12
plan needs 277.266 MiB but 9.275 / 8.884 times internal work (non-DD / DD).
These arrays were never allocated by the experiment. The symbolic count
does not demonstrate that a production proof fits either host RAM or VRAM.

Baseline potentially eliminated: gross original U8 helper data and its
processing, only under a reviewed replacement. Added work: fractional nodes,
recomputation, leaf generation, original ordered A links, one bound global
histogram, all denominator refusals, reductions, fresh masks/CFS rows, terminal
claims/PCS openings, transfers and launches. Other H/M data remains. Exact
net bytes, actual GKR mask/claim sites and time are **unknown**. The JSON has
`actual_GKR_CFS_PCS_mask_sites: null`; 84 private root pairs and 83 ordered
column links are semantic obligations, not 84 public messages or 83 mandated
independent PCS openings. All intermediate/root arrays remain private.

With unknown exclusive affected elapsed fraction f, even free deletion has

candidate on changed exact relation/refusals, unbound leaves/histogram,

avoided cost. A speed experiment also needs actual capacity and phase clocks.

## Model and validation

`schedule.py::plan(sizes, cached_depth)` counts a mixed-height forest with
one table and retained top caches. A lower layer is regenerated by independent
DFS block reductions, supplied as a complete array, consumed and discarded.
All top caches and root joins conservatively remain live. The storage bound
includes a service array and DFS frontier; it excludes the consumer's folds,
sumcheck scratch, original A/model, other H/M, encoding/Merkle storage,
fresh masking and terminal opening storage. No GPU allocator behavior is modeled.
The one-column alternative builds all private roots once, then reconstructs
and retains one complete column tree for its top-down consumer.

`serve` executes only tiny cases; its test harness retains output copies to
compare them with an independent bottom-up tree. This harness is not the
claimed streaming implementation or a proof-memory measurement.
`reference.py` independently enumerates tree widths and compares direct
inverses over F65537. This field is an arithmetic oracle, not native Fp2.

Probe: **959 checks, 10 public fixtures, 116 tiny schedule cases, 9 controls**.
Audit: **5641 checks, 1500 cost mutations, 1000 tiny column services,
30 mixed-height root checks and five unchanged native source pins**.
Wrong-site permutation retains the same fractional root while the ordered
leaf binding changes: a root-only check is insufficient. Dropped multiplicity,
duplicated global histogram, zero denominator with zero multiplicity,
degenerate `(0,0)`, cross-attempt inverse reuse and floor-width stacking have
explicit controls. They do not replace native refusal/privacy tests.

The first run hit division by zero when reporting a work ratio for a singleton
tree, whose construction has zero internal nodes. The ratio is now `null`
for that case. Original code, failing log and command are preserved under
`before-singleton-ratio-fix/`; no production finding is implied.
