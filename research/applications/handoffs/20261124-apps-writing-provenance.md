# What a writing-history receipt can establish

A reader could verify that the published text came from an identified editor session, beginning at an agreed draft, through the editing operations allowed by a named policy. The author could keep deleted passages and precise typing times private. A person transcribing a model answer can produce a genuine typing history. A defensible label would say **writing history verified** and identify the recorder, starting document and allowed input methods. [Music provenance design, sections 1–3](../../../docs/provenance/MUSIC_PROVENANCE_POC.md)

## What existing editors record

- Grammarly Authorship reports source categories for document spans and offers playback. Its documentation describes gaps when typing is too fast to capture and when the software cannot attribute text pasted from another application. A recorder needs an explicit “unknown” category whenever tracking starts late, resumes after a gap or cannot identify an input. [Grammarly Authorship guide](https://support.grammarly.com/hc/en-us/articles/29548735595405-Introducing-Authorship)
- Turnitin Clarity displays draft playback, writing sessions, revision activity and external pastes. It distinguishes pasted text later edited from pasted text left intact. Copying within the document is excluded from its external-paste findings. Those two cases need separate treatment in an edit policy because moving an author's existing paragraph can preserve its source. [Turnitin Writing Report](https://guides.turnitin.com/hc/en-us/articles/36916426919949-Reviewing-the-Writing-Report)
- The W3C Input Events specification distinguishes composition, replacement, paste, drop, undo and redo. The text that reaches a document can be the result of an input method, spelling correction or assistive input. Define capture at the level of document operations and disclose which input methods the recorder can distinguish. An ordinary application event describes what the editor observed. It cannot independently certify a physical keyboard or its operator. [W3C Input Events](https://www.w3.org/TR/input-events-2/)

## What the proof would need

1. Start with a signed challenge for this session and a commitment to its initial document, empty or explicitly identified. The trusted recorder signs a final event count and a chained commitment covering sequence number, editor and policy versions, edit kind, affected range, new content and previous state. Salt private commitments to short edits so readers cannot enumerate their text. Commit any imported span and record its source class.
2. Replay each operation against the committed previous state. Check position bounds, removed extent, inserted bytes, preserved text on both sides and the surviving spans' source classes. Commit the result after each step. Pin the indexing, line-ending and Unicode rules. Undo must restore the earlier content and its source labels. A policy that disallows untracked imports must fail or mark the affected text unknown after interrupted capture.
3. Bind the final bytes to the public post or its salted content commitment. Prove the chosen policy over the full sequence. Release the permitted summary and keep draft contents, deleted text and individual timings with the author. The prover sees this private history, so running it on the author's device is part of that privacy claim. A trusted start challenge and externally timed closing checkpoint can bound the session interval. Exact timestamps inside the interval depend on the recorder's clock.

**COUNTED in a Python UTF-8 check.** The displayed word “Café” uses four Unicode code points and five bytes with precomposed `é`, or five code points and six bytes with `e` plus a combining acute accent. The strings normalize to the same NFC text. An edit offset or final digest can change if the recorder and verifier normalize at different stages. Preserve a specified byte representation through replay and identify any display normalization explicitly.

## What can be reused

The music spike implements an ordered SHA-256 capture chain and a simulated device tag. Its second prototype links committed audio mixing to the published master. The equality between the signed capture digest and the private values used in the proof is still supplied by the producer's construction. A text implementation must prove that equality. The media app already has a salted final-byte commitment, Ed25519 publisher signatures and Merkle inclusion. Its signing key authenticates the publisher. A recorder credential needs its own issuer, software identity and revocation policy. The new parts are trusted input capture, a private edit-replay relation and the link from its output to the signed post. The current classifier measures a model's verdict about content. ## Deciding test

Use synthetic sessions that finish with identical text. Type one from a blank draft, paste and edit a second, and manually transcribe a model-supplied copy for a third. A typed-input policy should accept both typed sessions and identify the pasted source in the other. Repeat with composition, internal copy, undo and an untracked interval. An independent reader must reject an omitted edit, spliced session, changed initial draft or changed final bytes. Inspect the public receipt for deleted text and per-event timestamps. The indistinguishable transcription is the test that rules out selling this as a human-authorship guarantee.
