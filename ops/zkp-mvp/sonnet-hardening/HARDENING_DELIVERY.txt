CHANGED FUNCTIONS (mvp_driver.rs)
  js()            full JSON escaping of any Rust string. `"` `\` short escapes; U+0000..U+001F (\b \f \n \r \t or \u00XX), DEL and U+2028/2029 as
                  \uXXXX; everything else, Unicode included, verbatim UTF-8. The 2048-character truncation and the '?' substitution are gone.
  pj()            NEW. Path as a JSON string via to_str(); a non-UTF-8 path renders as null, never lossily. Used for every path in prove_start,
                  prove_result and the failure record pointer (was js(display().to_string())).
  resolve_new()   now refuses a non-UTF-8 result path by name, so pj's null arm is unreachable in practice.
  sh_quote()      NEW. POSIX word quoting: [A-Za-z0-9_@%+=:,./-]+ passes through unchanged (simple paths unchanged); anything else, and the empty
                  string, is single-quoted with ' written as '\''. Nothing is executed or expanded.
  verify_argv(), shell_line(), argv_json()   NEW. prove_result.independent_verification now has
                    "command"        (same key as before, now the POSIX-quoted line of the argv, and it now also carries --expect-run-profile),
                    "command_quoting" (a note),
                    "argv"           (JSON array; argv[0]="zk60_private_stack", argv[1]="verify", then --artifact P --policy P --policy-sha256 H
                                      --expect-run-profile PROFILE). argv[2..] can be passed straight to verify_command.
                  Policy hash pin and run-profile pin are explicit in both forms.
  read_capped()   NEW. Read::take(max+1)+read_to_end; more than max bytes is refused and no more than max+1 are ever read. `hint` only sizes the
                  first allocation, capped at max.
  read_bounded()  now: symlink_metadata must say regular file (symlink, directory, FIFO, device refused BEFORE open, so a FIFO cannot block the open);
                  one File::open; handle metadata must again be a regular file; on unix the handle's (dev, ino) must equal the lstat's (a path swapped
                  for a symlink or another file between check and open is refused, not followed); size cap on the bytes read via read_capped. Error
                  texts kept: "not a regular file", "larger than the N-byte bound".
  scan_artifact() segment bytes now come through read_bounded (was symlink_metadata + std::fs::read); the `statement` entry is checked with
                  symlink_metadata and must be a real directory (was is_dir(), which follows a link).
  prove_inner()/record_failure()/prove_command() emit paths through pj and the argv/command above; HL_GPU read with var_os (a non-Unicode value
                  is reported as "<non-unicode>" instead of "unset").
  emit()          test-only capture hook (cfg(test) thread-local); production path unchanged.
  examples/zk60_private_stack.rs   std::env::args() (panics on non-UTF-8) replaced by args_os(); a non-UTF-8 argument exits 2 with a stderr message.
Symlink behaviour, stated: files read through read_bounded (policy, manifest, segments) are never followed if the path itself is a symlink
(unchanged acceptance, now race-hardened on unix). `statement` as a symlink is newly refused (it was accepted when the link pointed at a directory
holding the manifest). The --artifact directory argument itself may still be a symlink to a directory (unchanged; is_dir follows it). No-overwrite,
staging, publication order and the failure record are untouched.

REMAINING GAPS (precise sites, not fixed here)

    scan refuses a symlinked segment/statement first, but a swap AFTER my scan reaches run.rs. * run.rs:908 File::open(p) follows a symlink and has

    the refusal message can be ambiguous. * A FIFO swapped in after the lstat and before File::open can block the open (window is microseconds).
  * Non-unix builds skip the (dev, ino) comparison. * Error strings from the lower layers embed display() of paths (lossy for non-UTF-8); they go
    through js() intact but are not a faithful identifier. * The prove `--out`/`--policy-out` parents are canonicalised (symlinked parents resolved);
    `--artifact` and `--policy` of verify are used as given. * No JSON library is a dependency, so the test reader is local; if root prefers serde_json
