WHAT IT DOES (anchored)
  * Proves with run::prove_run (run.rs:531) and verifies with run::verify_run_from_dir (run.rs:898): one transcript, hidden
    internal boundaries. Not concatenated blocks.
  * Source: StackSource implements RunWitnessSource. It retains ONE current input (x) and at most ONE witness. prove_run calls
    boundary_plane(k) then witness(k) (run.rs:576, 588), so boundary_plane builds witness k, keeps it in `cached`, and witness(k)
    hands it over. Two passes, per ruling H-1 (run.rs:465-495): a SEALING pass (L builds, gives the two external planes before the
    header, inadmissible chains refused here) and the PROVING pass (L more builds). Counts are reported as witness_builds. At the
    last block the proving pass compares a blake3 of its output plane with the sealing pass's (in memory only) and refuses on drift.
  * Fresh randomness: prepare_endpoints (OS ZkRng inside endpoint_g::prepare) and prove_run (ZkRng::from_os, run.rs:551) draw fresh
    every proof. The test asserts two proofs of the same shape/blocks give different policies (endpoint roots).
  * Tokens: reported once (tokens = shape tokens); block_token_evaluations = tokens*layers is a separate field.
  * Scope in every result: scope string, synthetic:true, trained_model:false, trained_8b_proof:false, privacy_acceptance:false.
  * prove_result carries receipt_bytes, per-segment bytes+sha256, block/run profile, shape name, layers, dims, recipe, model_digest,
    calibration identity + scales, endpoint roots, policy sha256, independent_verification{available:true,
    performed_in_this_process:false, in_process_check:"passed", command}, witness_builds, timing_s, driver_wall_s, peak_rss_mib
    (run::peak_rss_mib process high-water mark).
  * Phases (timing_s keys, each also emitted live as a {"event":"phase"} line): model_setup, chain_prepass, endpoint_prep,
    statement, witness_build_recurring (proving pass, all recomputation),
    prove_and_serialize_excluding_witness_io (prove_run wall minus witness build minus sink; wire::encode_segment runs INSIDE
    prove_run, so segment serialization is INCLUDED here and is NOT separately instrumented),
    stage_io (DirSink write+fsync+SHA-256 only), verify_setup_inprocess, verify_inprocess, publish. driver_wall_s is command wall
    from argument parsing to result. It excludes process start/exit and is labelled so; tokens_per_s_over_driver_wall uses it. Nothing
    is labelled end-to-end from prove_run alone. Root adds process-level totals and GPU evidence.

TRUST MODEL OF verify
  Only the caller's policy file (zk60-mvp-policy/1, written by prove OUTSIDE the artifact) and pins are trusted. Policy = shape,
  blocks, recipe, context label, model-digest root, both external endpoint roots; every other line (block/run profile, tokens, dims,
  context, calibration, scales) is DERIVED by this build and the text must equal its own canonical re-render, so a foreign profile,
  wrong calibration, wrong count or wrong context is refused by named line. verify then regenerates the public weights from the recipe,
  refuses unless their digest root matches the policy, rebuilds the RunStatement and ExpectedIo from the policy alone, and runs
  verify_run_from_dir. The manifest in the artifact is only COMPARED (re-rendered from policy sha256 + segment lengths/sha256, must be
  byte-equal); nothing is adopted from it. NOTE: the policy's endpoint roots are prover-created (D18). A verifier who takes the policy
  from the prover has accepted those roots; whoever owns that decision owns it. That is a channel question, not something I can enforce.

PUBLICATION / FAILURE
  segments -> <out>.staging (DirSink, atomic per file) -> in-process verify from a statement rebuilt from the policy TEXT -> manifest ->
  policy written (create_new) -> rename staging to <out>. Nothing exists at <out> before that. Existing <out>, <out>.staging or
  --policy-out are refused (exit 2); nothing is overwritten or auto-deleted. On failure the driver deletes ONLY files it made
  (segment-NNN.bin[.partial], the manifest), writes failed-attempt.json (phase, named error, timings, segment lengths/hashes, no
  private value) and renames the staging dir to <out>.failed-<unix>-<pid>. No segment survives a failed attempt.
  Refusal matrix (test): modified segment, swapped segments, missing segment, extra file, other run's policy, wrong pinned blocks /
  shape / input root, policy byte edits, extra policy line, no final newline, oversize policy. Segment files are bounded by
  wire::MAX_WIRE_BYTES_ANY, policy 16 KiB, manifest 64 KiB, blocks <= 64; no length in a file controls an allocation.

BLOCKERS FOR TRAINED TINYLLAMA / LLAMA3-8B (each anchored; none is fixable inside my lane)
  Reference geometries (corrected): TinyLlama = 22 layers, width 2048, FFN 5632, Q32 / KV4 / dh64. Pinned plain Llama3-8B = 32 layers,
  width 4096, FFN 14336, Q32 / KV8 / dh128, rms_eps 1e-5, rope_theta 500000, no rope scaling. Host RAM ~15.4 GiB, GPU 8 GiB.
  See trained-calibration-next.txt for the calibration-parameter specification.
  B1 Calibration is one pinned constant pair. IoSpec::new_shaped refuses any scale but ENDPOINT_SCALES=(0,0) (private_block.rs:678),
     RunStatement::new refuses any block scale pair but that (run.rs:193-200, ruling R-5), and calibration_identity() is the digest of the
     literal "B3 public fixed calibration v1" (private_block.rs:318). A trained int8 model has per-tensor/per-layer exponents. Needs a
     new calibration identity that commits per-layer scales, absorbed in the header (run.rs:353) and R-5 replaced by a check against it.
  B2 Requantization shifts and tables are layout constants: SH_QKV/SH_ROPE/SH_S/SH_O/SH_AO/SH_G/SH_H_PROD/SH_Z, NORM_TN/NORM_CN (layout.rs:62-80),
     RoPE base is 10000.0 in every current rope_tables_generate call (grow_tests/dense_tests/mvp_driver block_of); it is a table-generation
     ARGUMENT (tables_attn.rs:142), so pinned plain Llama3-8B's 500000 with no scaling is a public-table change, not an equation change.
     Activation table is SiLU (-3,-11), one of nine frozen registry members. A trained checkpoint must be quantized so these match, or they
     become Shape/statement parameters. This is the main correctness risk and needs the reference kernel (private-block-kernel-shaped) to
     define the quantizer. The exact minimal parameter list is in trained-calibration-next.txt.
  B3 Whole-model public weights are resident. prove_run and RunVerifier take `blocks: &[BlockPublic]` (run.rs:531, 672) and the header
     absorbs every digest up front (run.rs:254-261, 351). m125 is ~9.2 MB/block (run_tests.rs:1353-1357). Resident public words for all layers of a
     larger model have NOT been sized here; against 15.4 GiB host RAM and 8 GiB GPU the whole-model-resident design must be sized from the
     padded statement, not assumed. Needs a streaming provider (block k's public words on demand at run.rs:571 and 736, digests from a
     pinned manifest) on both prover and verifier sides.
  B4 Witness size. Witness.planes is Vec<Vec<i64>> (witness.rs:45); ~711 MB at m125/512 tokens (run_tests.rs:1353-1357). The trained-shape
     witness has not been sized here; whether one witness fits 8 GiB / 15.4 GiB must be counted from the padded plane list, and if it does not,
     it needs plane-wise / slot-wise streaming or token chunking with a KV carry (a statement change: causal attention across chunks).
  B5 Shapes are a closed set with measured admissibility. Shape::new geometry rules and RunShape only cover registered shapes; TinyLlama
     (22 layers, 2048, 5632, Q32/KV4/dh64) and plain Llama3-8B (32 layers, 4096, 14336, Q32/KV8/dh128) have no Shape, no profile string
     (D17), no NTT size check (RunShape::ntt_log / fits_the_ntt_tables), no chain band (dense_tests.rs:344 falls back to an unmeasured formula).
     Trained weights make the band question moot but the int16 residual range (`residual 2` refusal) becomes a real-data property.
  B6 Throughput: NO forecast is made. Width alone does not determine proving time (padding, lookup counts, domain sizes and the GPU path all
     enter), and the only figure in the tree (run_tests.rs:1361-1367, CPU, m125) is a measurement of that shape, not a predictor. Only your
     measured runs at a registered shape count, and only per-phase timings from this driver over that shape.
  B7 Model boundary. D13 scopes the first MVP to all transformer blocks: embedding, final norm and lm-head sit outside the run, so the two
     external endpoints are hidden-state planes. Nothing here imports a checkpoint or defines who commits those endpoints for a real user (D18
     prover-created endpoints are a demo profile). Token generation (KV cache across steps) is a separate statement.
  B8 Privacy: narrowed run privacy tools exist, but there is NO accepted trained-model or run-level privacy statement. The run-level
     obligations named at run.rs:20-28 (joint rank over the three boundary commitments, cross-block blinding independence, run-wide joint law)
     are not accepted for any trained model. Passing verify is not an acceptance, and every result says so.
